# Agent Note: a machine picked once is not a machine to phone on every launch

Status: implemented

[English](2026-08-29-a-machine-picked-once-is-not-a-machine-to-phone.md) | 中文

## Problem

一個曾經選過遠端機器的人，連一段對話都開不起來。視窗打開了，然後什麼都沒發生；而在從 shell 啟動的那一份上，`ssh` 正在一個他根本沒在工作的終端機裡要密碼。

三件各自獨立的事湊成了這個結果：

**機器的選擇會被記住。** 它是設定，所以跨重啟保留——這是對的，也代表每一次啟動一開始就指向一台可能已經睡著、搬走、或金鑰還沒加進 agent 的機器。

**啟動時會拿每一個記住的 session 去問那台機器。** `WorkspaceRuntime.indexHeader` 透過 `ctx.fs` 正規化每個 session header 的 `cwd`，而 `ctx.fs` 是被路由的。在一個有十一個 session 的 profile 上實測：**UI 都還沒載入，就已經十一條 ssh 連線**，而沒有任何人要求過什麼。

**沒有東西阻止客戶端跳出提示。** `BatchMode=yes` 只設在 `probe()` 上，所以其他每一次調用都可以自由地要密碼——而且把子行程的 stdin 導成管線擋不住它，因為 OpenSSH 會開 `/dev/tty`。harness 於是等一個按鍵，而對一個視窗程式來說沒有人能提供那個按鍵。

合起來：一個被記住的選擇，把每一次啟動變成十一個阻塞的密碼提示，出現在沒有人看著的終端機上。

## Decision

**索引絕不碰任何人沒有要求的機器。** 當執行世界是遠端時，`indexHeader` 原樣記下 header 的 `cwd`，不做正規化。這個判斷透過 cordis 不拋出的選配查找讀取目前機器，所以一個沒有掛載機器簿的組裝——它本來就沒有別的機器可以在上面——不受影響，也不需要新的宣告相依。

這不只是「什麼時候連線」的問題。它問的本來就是錯的問題：header 的 `cwd` 是在那個 session 當初執行的機器上記錄的，而現在選中的機器未必是那一台。`/srv/app` 在兩台電腦上是不同的目錄，所以拿現在剛好是當前的機器去正規化一個記住的路徑，得到的是關於錯誤那台電腦的答案。在 header 帶著自己的機器之前，原樣記錄才是誠實的答案。

**沒有東西可以在沒人看著的終端機上要密碼。** `argvFor` 在除了終端機工作階段以外的每一次調用上加 `BatchMode=yes`。拒絕變成 OpenSSH 自己的那一句——`Permission denied (publickey)`——那是介面可以顯示、而人可以用「把金鑰加進 agent」來處理的。真正的終端機工作階段（`-tt`）保留提示，因為那一個人就是在看著它，而在那裡跳出通行碼提示代表連線正在運作。

這條規則住在 `argvFor`，因為每一條會連線的路徑都在那裡組 argv：`fs-ssh` 兩處、`subprocess-ssh` 三處。一個收斂點，一條規則。

## Alternatives considered

**延後連線，但仍然在索引時做。** 把同樣的十一條連線推遲到第一次渲染，只是把停頓搬個位置，而不是移除它；而且那個答案仍然是關於錯誤的機器。

**啟動時丟掉記住的機器。** 它用「扔掉使用者的選擇」來消除連線，產品上更糟：他是刻意選那台機器的。

**改成由 app 來問密碼，而不是終端機。** 那是一台真的需要通行碼的機器該有的最終樣子，而且大得多：需要 UI、需要一條在沒有 tty 的情況下把祕密交給子行程的路徑，以及儲存它的政策。批次模式是今天讓失敗看得見的東西；那是前置條件，不是替代品。

**把機器記進 session header。** 那是後半個問題的真正答案，而它會改動一個持久格式。留作後續：有了它，一個記住的路徑就能對著它真正所屬的那台機器正規化，而不是完全不正規化。

## Consequences

無論記住的是哪一台機器，啟動都不再執行任何遠端工作；而一台無法非互動驗證的機器會公開地失敗，不再卡在提示後面。

代價是遠端 session 記錄的 `cwd` 不再是正規化過的：符號連結與 `..` 都原樣保留，所以在遠端機器被選中的期間，兩個用不同拼法指向同一個目錄的 header 不再被併成同一個 workspace。那只會表現為分組重複，而它嚴格優於一個在錯誤電腦上算出來的答案。

## Verification

對著跑起來的 harness 量測，用一台解析不到任何地方的機器與十一個記住的 session：**改動前啟動時十一次 ssh 調用，改動後零次**，計數方式是把一個會記錄的 `ssh` 放進 harness 的 PATH。

提示規則由兩個測試釘住——指令帶 `BatchMode=yes`、終端機工作階段不帶——拿掉任一半都會讓其中一個變紅。
