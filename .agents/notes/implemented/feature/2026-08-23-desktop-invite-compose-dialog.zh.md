# Agent Note: 桌面端邀请模态框，以及设计超出数据的四处

Status: implemented

[English](2026-08-23-desktop-invite-compose-dialog.md) | 中文

## Problem

「邀请好友」页面列出账号的推荐状况，并在旁边放了一个内联地址输入框与发送按钮。同一件事随后来了一份参考设计，画成模态框：一条头图带着产品标记、一条绿色提示条写明每次邀请的奖励并在右侧放一个资格条件链接、居中的标题与说明、一个地址输入框，以及一颗在地址说得通之前保持关闭的胶囊发送按钮。

其中三处描述的是本产品并不持有的事实。`UnieAiInvites` 回报的是已积攒的速率限制重置次数、已发送数量，以及那些已发出的邀请；没有任何字段回报奖励**比率**，账户契约、桌面 BFF 与 `packages/unieai/web-gate` 之中也没有任何字段承载条款 URL。产品标记确实存在，但它住在本包够不到的地方。第四处——输入框本身——页面上已经有了，在模态框里再画一次，就等于同一个画面背后有两个撰写框。

设计不能靠往空处填看似合理的数字来实现：在此编造的奖励数字，是产品从未做出的承诺；而没有目标的链接比没有链接更糟。

## Decision

**撰写迁入 `InviteFriendDialog`；页面保留状况，并获得一个入口。** 卡片画的是已积攒的重置次数、已发送数量，以及带各自复制控件的已发邀请；`invite.compose` 打开对话框，由它持有输入框、发送按钮与 `UnieAiInviteResult` 的四种结果。入口只在网关提供 `sendInvite` 时存在，因此推荐功能只读的部署显示的是一份摘要，而不是一个打开后无法发送的对话框的按钮。

**奖励条打印的是比率行，而不是一个数字。** `invite.reward`——「1 次速率限制重设 / 每次邀请」——是本包字典早已在四种语言里承载的推荐条款，而且它天然就是固定文案：比率是方案的条款，不是逐账号的读数。`UnieAiInvites.credits` 是已经积攒的余额，那是另一个事实，仍留在原先的页面上。奖励条里没有任何内容是从账户算出来的，参考设计里的点数数字则不出现在任何地方。

**资格条件链接是缺席，而不是失效。** 从分区到产品之间的任何一层都不存在可供打开的条款 URL，因此提示条不带该链接发布。

**头图方块画的是邀请自身的主题，而非产品标记。** 该标记是 `ui-brand-unieai` 提供的 `sidebar.brand.mark` slot 占位者。跨插件协作只走 slot 与服务，绝不走值导入，而 `settings.section` 条目不声明任何子 slot，因此本包两条路都够不到那枚标记。方块在白底上画 `IconUserOutline16`。这处替换记录在两份 README 的「已知限制」里，因为真正的修法是一个设置页面能够渲染的品牌座位，位于本包并不拥有的包中。

**在地址说得通之前，发送保持关闭**，由 `isPlausibleEmail` 判定：一个本地部分、一个 `@`、一个带点的域名。这是格式上的预检，而不是产品规则的第二份副本——哪些地址可接受、哪一个是账号自己的，仍由供给方裁定，并以 `invalid-email`、`self-invite`、`already-invited` 回来。该判定在 `submit` 中执行，而不只作用于按钮，因此直接提交表单也无法绕过。

**头图是本包唯一一块固定色板。** 它在两种调色板下都是同一条品牌蓝色带、托着一枚白色方块，因此取用与调色板无关的 `--dsw-static-deepseek-*` 色阶——`ui-theme/src/styles/design-platform.css` 写明该色阶承载 UnieAI 品牌蓝——以及 `--dsw-static-neutral-00`。换成 `--dsw-alias-*` 填充会把它翻成「白块压深色带」。头图以下的一切仍由主题决定：提示条使用 `state-success-*` 家族，字体使用 `label-*`，圆角取自共享刻度，样式表不写任何字面颜色。`tests/styles.client.spec.ts` 同时钉住这道分界的两侧，也钉住那两个双写类选择器（`.dialog.dialog`、`.field.field`）——无论样式表顺序如何，它们都胜过 `Modal` 与 `Input` 原语自带的几何。

提示条的图标是 `IconRefreshOutline16` 而非参考设计里的硬币：`ui-primitives` 中没有硬币字形，而一次邀请换到的正是一次重置。

## Alternatives considered

**保留内联撰写框，并在旁边加上对话框。** 同一个画面上、同一件事有两个地址输入框，差别只在于打开的是哪一个。页面自己的文案早已否决了同一主题命名两次；第二个撰写框正是那种失败再附带状态——两者可以持有不同的草稿与不同的裁定。

**把对话框放到账户菜单的「邀请好友」行背后。** 该行在 `unieai-invite` 处打开设置面板，而面板的导航正是告诉读者「这个主题是一个可以再回来的地方」的东西。用模态框取代页面会删掉推荐状况——余额、数量、已发邀请及其链接——而这些无处安放。

**把 `credits` 放进奖励条。** 它确实是一个贯通上来的真实数字，而这恰恰是它不能待在一行读起来像比率的文字之下的原因：在「一次邀请能换到什么」之下写着余额 2，陈述的是假话。它留在页面上，由 `invite.credits` 明确称之为余额。

**给资格条件链接一个看似合理的目标**——产品的市场站点，或邀请接口的来源域。两者都是对一个无人确认存在的页面的猜测，而一个 404 的链接让读者付出的代价比缺席更大。

**把 UnieAI 标记的路径数据复制进本包。** 十五行 SVG，此后品牌图形就有了两个家，并会在下一次品牌变更时各走各的。

**使用 `ui-primitives` 的 `FishLogo`。** 它是本包完全可以做的值导入，而它是 DeepSeek 的鱼：给未装载品牌占位者的组合使用的侧边栏回退。发布的桌面版装载了 `ui-brand-unieai`，因此这条鱼在本产品别处都不出现，把它放上邀请头图等于为错误的产品打了品牌。

**按供给方的方式校验地址。** 做决定的是供给方的规则集，而此处更完整的正则只会在本包无法测试的情形下与它分歧。这道预检刻意只取「低于此形状请求根本不可能成功」的那条线。

## Consequences

- 发送一封邀请现在多了一次按下才出现输入框。作为交换，页面陈述账号的状况，而下方不再压着一个表单。
- 对话框复用 `invite.title`、`invite.body`、`invite.reward`、`invite.emailPlaceholder`、`invite.send` 与那几行拒绝文案；`invite.compose` 是唯一的新键，已加入四个语言包。同一个画面上读到两次的文案——页面标题与对话框标题——分处两个界面，其一遮住另一。
- 参考设计的奖励数字与资格条件链接没有对应的实现，在供给方回报比率与条款 URL 之前也不会有。两者都记录在 `packages/client/ui-unieai-account/README.md`。
- 头图是本包唯一直接画出 `--dsw-static-*` 名称的地方。样式 gate 把样式表的其余部分限制在语义别名上，因此这处例外无法悄悄扩散。
- `tests/invite-friend-dialog.client.spec.tsx` 钉住关闭态的发送门槛、直接提交的绕过、飞行中的冻结、四种结果，以及对话框中不存在任何邀请链接或邀请码。
