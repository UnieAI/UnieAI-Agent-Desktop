# Agent Note：把詳情欄做成分頁容器

Status: implemented

[English](2026-08-25-details-column-as-tab-container.md) | 中文

## 問題

右側欄原本就是「一個被選取的工具呼叫」。它只會在點擊訊息流裡的工具列時作為副作用開啟,而開啟一個就會取代整欄——於是這一欄自己能回答的東西全都碰不到,而且除了關掉它以外沒有回頭路。

這個形狀藏起了兩件值得有的東西。工作階段本來就知道自己寫過哪些檔案:每一個都是一次已結算的工具呼叫,路徑就在它的參數裡。而工作區是一個 Host 列得出來的目錄。兩者都不需要新資料,只需要一個容身之處。

## 決定

這一欄是分頁容器。每個開啟的東西都是一個分頁——工作區樹、一個檔案、本次產出、一個被選取的工具呼叫——而 `+` 提供的正是空狀態那張選單。

**被選取的呼叫和其他分頁一樣是一個分頁**,但它的選取狀態留在共用的 chat store,因為訊息流也會寫它。同一個事實有第二條寫入路徑,只會讓兩者對「現在開著什麼」產生分歧。

**檔案透過兩條各自受限的 Host 操作讀取**,而不是一條通用的。`host.listWorkspaceEntries` 回名稱;`host.readWorkspaceFile` 回文字。兩者都接受一個工作區註冊表已經持有的 `root`,並拒絕解析到它之外的路徑;判定用 `relative()` 而不是字串前綴——`/w/project-secrets` 的開頭是 `/w/project`,但它不在其中。讀取還多受兩重限制:一個由部署設定的大小上限,且**在讀取之前**檢查(上限的意義就是不讓那些位元組上線),以及一個 NUL 位元組偵測,寧可不給二進位內容也不要滿畫面的替代字元。

**沒有對應的寫入操作。** 讀取是把工作區公佈給頁面;寫入則是讓頁面能改動它。那是另一個決定,要有它自己的圍欄。

## 考慮過的替代方案

**維持面板是「選取的呼叫」,另開一個介面放檔案。** 否決:兩欄搶同一份寬度,而且各自都還有同樣的「沒有回頭路」問題。

**一條通用的 `host.readFile`。** 否決:圍欄正是「公佈檔案內容」這件事站得住腳的原因,而通用操作沒有可以圈的 root。

**用 `directoryPicker.browse` 提供樹。** 它已經開給瀏覽器了,但否決:它的 `entries` **只有目錄**,因為它的用途是「挑一個工作區」——它能到達 Host 帳號讀得到的任何地方,而那正是這個介面不該有的觸及範圍。

## 後果

空狀態的欄位現在會回答,而不是叫人去點別的地方。長路徑在自己的軌道裡捲動,控制項留在原位。被截斷的清單會說自己被截斷,而不是假裝完整。

這一欄的上限是拖拉的夾制,不是能力上限:最大化會**離開**整條讓步鏈、把中欄壓到 0 寬度,因為「下限」正是這個狀態要擺脫的東西。
