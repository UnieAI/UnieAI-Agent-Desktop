# Agent Note: 桌面版任务完成通知

Status: implemented

[English](2026-08-22-desktop-task-completion-notifications.md) | 中文

## Problem

UnieAI Copilot 网页产品在后台任务结束时会告诉你：一条推送通知，加一段你选定的音效。桌面版则悄无声息地结束。把网页产品那一页照搬过来会撞上一个错配：它的通知块是 Web Push——一个 Service Worker、一个 VAPID 签名的发送端，以及一份服务端订阅存储——并承诺在「背景**或关闭应用**时」也能送达。本仓库这些统统没有，而本该发出推送的那个进程，正是用户关掉的那个。

因此问题不是「把页面移植过来」，而是「本地主机究竟能做什么，以及页面该如何诚实地描述它」。

## Decision

`packages/client/ui-settings-notifications` 以 order 5（位于「通用」与「模型」之间）注册一个 `settings.section`，包含两块内容，并同时拥有这两块所描述的行为。

**完成是推导出来的，不是推送来的。** 会话列表本就为每个会话携带 `running` 位——侧栏的活动圆点读取的正是它——因此 `SessionCompletionWatcher` 订阅 `ctx.sessions.list`，把某一行的 running→idle 边沿视为一次回合结束。不订阅 Host，不新增链路流量。两条守则保证这个边沿可信：短于 `MIN_RUN_MS`（2 秒）的运行是打开会话时的抖动而非任务；首个快照不触发任何东西，因为加载时就已空闲的会话，其结束发生在无人可被告知之时。当窗口可见且该会话正是屏幕上那一个时，这次完成被视为*已被注视*并直接丢弃——结束本身已经宣告过了。

**第一块是浏览器的 `Notification` API，不是 Web Push。** Host 通过 `127.0.0.1` 提供页面，属于安全上下文，因此窗口位于背景时弹出的通知能进入操作系统的通知中心。权限提示只能由「启用通知」按钮的点击触达：没有用户手势的提示会被拒绝，而 Chrome 会把这次拒绝永久记在该源头上。浏览器一旦作答，该块就渲染成一句话而非控件——页面无法撤销已授予或已封锁的权限，而一个开关不了任何东西的开关，比一句事实陈述更糟。可见性变化时会重新读取权限，因为在站点设置中的撤销永远不会通知页面。

**第二块是网页产品的音效选择器，整体照搬。** 十一个音效名与 `unieai:notify-sound` 存储键都取自网页产品，让那边做过的选择在这里能被认出；该偏好按设备存放在 `localStorage` 而非同步，因为哪种音效合适取决于具体机器。点击一个音效即同时选中并试听。音频位于 `apps/web/public/sounds/notify/<id>.wav`；`dsh-host-frontend-static` 为此新增了 `audio/wav` 的 MIME 条目，好让媒体元素愿意解码它们。

只要完成未被注视，无论通知是否获授权，提示音都会播放——这是页面中无需向浏览器索取任何东西的那一半。

**名字取自网页产品，音频属于本仓库。** 本功能的第一版复制了 `copilot-v2` 的音频，而那个仓库记述其剪自 iOS 17 音效集——Apple 的音频，落在一个 MIT 仓库里，且未记入 `THIRD_PARTY_NOTICES.md`。它们已被十一段合成音效取代：叠加的正弦分音、频率滑音，`rattle` 用经过滤波的伪随机噪声，每一段都由几毫秒的起音与指数衰减包络塑形，写成单声道 16 位 44.1 kHz WAV。没有任何录音或采样，因此这套音效是本仓库的原创作品，随本仓库自己的许可证发布，无需任何第三方声明。id 与标签均未改变，已存下的偏好仍能解析。

**文案取自网页产品四种发布语言的词条**，仅有两处偏离，且都朝着这个构建真正能做到的方向：该块标题为*桌面通知*而非*推播通知*，其描述去掉了「或关闭应用」一句。

## Alternatives considered

**照样交付 Web Push 那一块，但背后什么都不接。** 它会与参考实现像素级一致，并且在撒谎：开关会去索取一个永远没有发送端会用到的权限。任务本身的规则——不要交付什么都不做的开关——已经裁定了这一点。

**真的把 Web Push 建起来。** 需要 Service Worker、一对 VAPID 密钥、Host 侧的订阅表以及发送端。发送端是症结：要兑现「或关闭应用」的承诺，它必须活得比本地 Host 进程更久，也就意味着一台本部署并不具备的服务器。故记为限制而非尝试实现。

**直接消费会话管理器已有的 `completed` 位**，而不自行推导边沿。管理器只为*未选中*的会话点亮该提醒，因此在隐藏窗口后面、你正打开着的那个会话结束时，永远不会宣告。就地推导边沿也让抖动阈值留在真正关心它的包里。

**把音频以 base64 data URI 内嵌进客户端包**，从而既不写 `apps/web/public` 也不加 MIME 条目。代价是整套约 660 kB 的未压缩 WAV 变成约 880 kB base64，进入每个客户端启动即加载的包，只为省下 MIME 表里的一行。

**仅在通知权限已授予时才播放音效。** 这会把两块绑在一起，但网页产品的选择器并无此门槛，而音效恰恰是无需向浏览器索取任何东西就能工作的那一部分。

## Testing

`packages/client/ui-settings-notifications/tests` 下七个套件（51 项断言）：音效目录与存储往返，含敌意实现与缺失的存储单元；权限端口覆盖每一种访问值、会拒绝的 `requestPermission`，以及要求 Service Worker 的构造器；监视器的边沿、阈值、注视、移除与重启语义；控制器的单次提示规则、音效持久化与宣告门控；分区在每种权限状态下的渲染；以及一个在真实 `SlotRegistry` 与 `LocaleRuntime` 上端到端驱动伪造会话列表的组合套件——一次结束的回合产生音效加一条带 tag 的通知，被注视的那次两者皆无，纤程销毁则清空插槽并解除列表订阅。`dsh-host-frontend-static` 在其既有的真实组合套件中新增了一条 `audio/wav` 断言。生成的音频逐个解码核对过：时长、峰值电平、RMS 响度、首尾样本为静音，以及整套之间两两的频谱相关度。

## Consequences

桌面版现在会在工作结束时告诉你，且只用到客户端本就知道的信息。代价是这一页的触达范围止于打开着的文档：关闭应用即终止通知；而在应用关闭期间开始并结束的回合，按设计不可见——它只会表现为加载时就已空闲的会话。

音频是本仓库自己合成的，可与代码一样以 MIT 许可证再分发，也无需写入 `THIRD_PARTY_NOTICES.md`。它们不是的，是设计过的音频：这是一批生成的音调，靠测量而非在各类扬声器上试听来验证，并且因为工具链没有音频编码器而以未压缩形式发布。
