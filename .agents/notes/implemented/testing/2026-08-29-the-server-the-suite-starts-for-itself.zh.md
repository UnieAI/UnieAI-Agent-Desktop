# Agent Note: the suite starts its own server, because skipping was the default

Status: implemented

[English](2026-08-29-the-server-the-suite-starts-for-itself.md) | 中文

## Problem

有四個套件在證明遠端機器可以運作：機器簿對著真實伺服器、真實機器上的檔案、一台機器上的同一個世界、以及在機器之間切換。四個全部都是 `describe.skipIf(!ready)`，而 `ready` 的意思是兩個指向「某人手動架好的伺服器」的環境變數。

在每一次一般執行裡，以及在 CI 裡，四個全部**靜靜地跳過**。三十二個測試被報告成不存在，而不是沒有執行；遠端這條路就這樣完全沒有自動涵蓋地出貨了。

有三個缺陷透過這個缺口抵達使用者，而每一個都是「真的連一次、第一個指令就會發現」的那種：

- 一個被手動建構、卻沒拿到所需機器簿的路由 subprocess provider，於是選了遠端機器之後**每一個**指令都會失敗——包括本機的 `echo`——錯誤是 `cannot get property "ssh" without inject`；
- 一個可以自由地在行程繼承來的任何終端機上要密碼的客戶端，它會讓指令停住，直到有人在一個他根本沒在看的終端機裡打字；
- 一個從 `HOME` 解析出來的設定檔路徑，而 OpenSSH 讀的是密碼資料庫，於是機器清單和連線可能讀到不同的檔案。

單元測試看不見第一個：一個對著裸 `Context` 建構出來的服務會變成直接屬性，而 context proxy 回答它時根本不會去查注入。只有組裝會把服務掛進 fiber，也只有那時未宣告的讀取才會被拒絕。

## Decision

**套件自己起伺服器。** `@unieai/uad-ssh-server` 在 loopback 上跑主機的 `sshd`，連接埠由作業系統挑，主機金鑰與用戶端金鑰為那一次執行產生、結束後刪除。它只認金鑰、直接拒絕密碼，所以套件裡沒有任何東西能卡住等一個人。

`DSH_SSH_TEST_CONFIG` 與 `DSH_SSH_TEST_ALIAS` 兩個都設好時仍然優先，所以任何人都可以改成指向一台真的機器。改變的是退路：它過去是「全部跳過」，現在是「起一台」。

**跳過只剩下一個理由，而且它會說出自己是誰。** 一台沒有 `sshd` 的機器跑不了這個 fixture，而訊息會說出它找過哪些路徑、以及哪兩個變數可以改為指定一台伺服器。它取代的正是沉默。

**Fixture 本身是被證明的，不是被假設的。** 一個對著不存在的伺服器「執行」的 fixture，只是用另一種沉默取代原本的沉默，所以它自己的測試會用真正的客戶端連線，並斷言 `SSH_CONNECTION`——那是只有 sshd 會設的變數——因為在 loopback 上，主機名證明不了任何事。第三個案例把伺服器唯一接受的驗證方式拿掉，並斷言它拒絕，而不是跳出提示。

## Alternatives considered

**在 PATH 上放一個假的 ssh 執行檔。** 便宜，而它只證明了這個 repo 呼叫得動一個同樣由它自己寫的東西。argv 之所以是有趣的部分，正因為必須由真正的客戶端接受它。

**用容器。** 可重現但很重：它需要 CI 和每個開發者機器上都有一個 runtime，而那是一個比「大多數 POSIX 系統本來就有的執行檔」大得多的相依。

**保留環境變數這道門，然後在 CI 裡設好。** 那修好了 CI，卻讓每一次本機執行都沒有涵蓋——而本機執行正是這三個缺陷最早會被感受到的地方。

**讓套件繼續跳過，靠人工測試。** 那就是產生這些缺陷的狀態。

## Consequences

三十二個遠端測試現在每一次 `test:e2e` 都會跑：機器簿七個、檔案十五個、單一世界四個、切換六個。argv、注入或提示政策的迴歸，會在任何人安裝之前就被抓到。

代價是相依於 `sshd` 有被安裝。在沒有它的機器上套件仍然跳過——但它會說出來，而且訊息是可行動的，那正是「缺少的涵蓋」與「沒有人知道缺少的涵蓋」之間的差別。

## Verification

對著乾淨樹，e2e 執行回報 35 通過、34 跳過；加上 fixture 之後回報 39 通過、30 跳過，而且四個套件各自單獨跑過一次，確認它們是執行而不是跳過。

Fixture 自己的三個測試對著它啟動的伺服器通過，包括那個證明指令真的跨過連線的 `SSH_CONNECTION` 斷言。
