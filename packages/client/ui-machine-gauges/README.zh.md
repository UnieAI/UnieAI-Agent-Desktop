# @unieai/uad-client-ui-machine-gauges

[English](README.md) | 中文

session 标题列上两三条小小的横条，说明这段对话所跑的那台机器正在做什么；后面还有一个面板，放剩下的读数。

## 它坐在哪里，以及为什么在那里

就在**视图切换的前面**，位于标题列右侧那一组里。当一个人想知道的是「这个 session 的事」而不是「眼前这则讯息的事」时，视线本来就会往那里去。

这个顺序是契约，不是偏好。仪表描述的是**机器**；旁边那个切换讲的是这一栏正在显示什么。画在切换后面的读数，会被读成那个视图的属性。所以本套件注册进 `conversation.session.header.gauges`，由 [`ui-conversation`](../ui-conversation/README.zh.md) 在切换之前渲染，并且有一个测试把这个顺序钉住。

session 还空白时标题列会自己隐藏，所以这条横条是跟着 session 的其他外框一起出现的，不会更早。

## 小，而且对「量到了什么」诚实

三条横条，没有数字，也没有图表。标题列是拿来「注意到某台 build box 被打满了」的地方，不是拿来研究它的地方；所有带数字的东西都在横条后面的面板里。

**没量到的读数不画横条。** 选定一台机器之后的第一轮不报处理器百分比——它是两次读数之差——而一台没有 `/proc` 的机器则永远不报。那里画一条空的，等于说这台机器闲着，而这跟「没量到」是两回事，所以横条就少一条。同一条规则也会在只读到分数的一半时拿掉内存条，以及拿掉一个没有回报使用率的加速器。

顺序是「变得最快的排前面」：处理器、内存、加速器、磁盘。磁盘放最后，因为它是以小时为单位在动的。

## 只在画面上的时候轮询

每一次读取都是在某个人的机器上跑一条命令，所以它在有人看着的时候发生，没人看就停：横条挂载时开始轮询，卸载时停止，分页被切到背景时跳过。用推送的话，就等于在任何人曾经选过的每一台机器上永远跑着那条命令。

生命周期属于 view 而不是组件，而且它会数自己的读者——重新挂载不能留下一个计时器，第二条横条也不能开出第二个。轮询回来时若 view 已经停了，靠比对「它是在哪一个世代开始的」来丢弃；因为一个已经被编译器收窄过的布尔值，在 `await` 之后读起来会像永远进不去的死码。

**一次失败的轮询会留住上一份读数**，并把横条调淡。一会儿之前为真的东西，仍然是任何人手上最好的答案；断线就清空，会让一次小抽搐看起来像机器不见了。这时候打开面板，会说明这些数字是失败之前的。

**一个根本量不了任何东西的部署，什么都不画，而且不再问。** `metrics-unavailable` 只回答一次，之后这条横条回 null，而不是当一个永远答不出来的控件杵在标题列上。

## Model Experience

无。此套件只贡献浏览器端的呈现，不触及任何模型请求。

#### KV Cache effect

无；此套件不组装、也不发送任何东西。

## Known Limitations and Deferred Work

- **横条只显示第一个加速器。** 一台有八张 GPU 的机器只画一条，后面的面板才把它们全部列出来。标题列上八条横条就是一张图表，而那不属于标题列。
- **没有历史，所以没有趋势。** 每一份读数都覆盖上一份；要显示过去一分钟，本套件就得自己留一串数列，而它存在的意义是「一眼看到」，不是当一套监控。
- **四秒不可设定。** 这个间隔是一个常数，取的是「不要问得比一台慢链路上的远端机器答得出来的还快」。想换一个数字的部署，没有地方可以讲。
- **面板打开之前，没有任何东西说明这些横条描述的是哪一台机器。** 横条上没有位置放，而输入框那边的机器选择器已经说了工作跑在哪里；面板里会再说一次，因为摆在一个人面前的读数应该讲清楚它量的是什么。
