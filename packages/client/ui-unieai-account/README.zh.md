# @unieai/uad-client-ui-unieai-account

[English](README.md) | 中文

本包用同一份账户状态填两类 seat：侧边栏左下角的账户行，以及**三个** `settings.section` 条目，承载 UnieAI 网页版设置中属于个人的那一半 —— **账户**（你以谁的身份登录、你的 Token 活动，以及会话本身）、**剩余用量**（`常规使用限额`）与**邀请好友**。三者都注册在「通用设置」之前，且按此顺序排列，因此设置面板打开时首先看到的是使用者本人。

是三个页面，而不是一个页面上的三个锚点。剩余用量与邀请各自都是读者会专门打开面板去看的主题，而唯一能说明这一点的界面就是面板的导航；锚点跳进一个长页面的中段，只会让导航行仍然高亮着，而读者已经在看另一个标题了。每个页面在每种账户状态下都有内容；下文关于未登录的一节说明各自画什么。

本节刻意不承载任何平台、组织或企业向的内容。这不是靠人记住的规矩，而是数据契约的性质：[`src/account-contract.ts`](src/account-contract.ts) 声明的账户只有身份、方案**名称**、计量额度、活动序列与邀请状况，不存在席位、群组、审计、SSO 或账单字段可供组件渲染。

外观与语言在此刻意缺席。二者已经是「通用设置」中的行，由拥有该偏好的功能各自贡献 —— `ui-theme` 提供外观，`locale` 提供语言 —— 因此本节只用一行说明它们在哪里，而不是给同一个偏好第二个控件。

## 侧边栏账户行

`sidebar.account` 是侧边栏最后一行的左半边，由本包填入。它读取与本节相同的数据源，渲染出 28px 圆形身份标记与占据余量的 13/500 显示名称，除此之外没有别的。它们外面的行**盒子**不属于本包：设置图标与之共用同一行，因此那条 248x40 的行（`6px 8px` 内边距、10px 间距——正是 UnieAI 网页版给自己那一行用户行的几何：`rounded-lg px-2 py-1.5`、`gap-2.5`、`h-7 w-7 rounded-full` 标记）归侧边栏页脚的身份 seat 所有，本占位者不再画第二个盒子。56px 轨道只在该 seat 的 36px 控件中保留标记，把这行文字移入其 tooltip。

这一行是**菜单触发器**，与 UnieAI 网页版自身侧边栏页脚一致：带 `aria-haspopup="menu"`，按下后向上打开账户菜单。只有身份那一半是触发器——旁边的设置图标是独立控件，与参考实现完全相同。它的悬停填充会反向越过 seat 的内边距，并在那枚图标之前的间距中点止步。

这一行**显示**什么仍由状态决定，而非布局。`unavailable`——没有网关的组合所处的状态——画一个人形字符并说明尚无人登录。只有 `signed-in` 会写出一个人的名字，且其中每个值都来自 `UnieAiAccount`。

## 账户菜单

菜单的顺序、条件与行为取自参考实现的源码而非截图：账户抬头，随后是「个人档案」「剩余用量」「邀请好友」、外观行、带子菜单的「语言」，再是一条分隔线与「登出」。它以 `side="top"`、`align="start"` 打开，距触发器 8px。

每一行都接到 dsh 已经具备的能力上；背后空无一物的行不会被画出来：

- **个人档案／剩余用量／邀请好友**分别在本包的三个分区打开设置面板 —— `unieai-account`、`unieai-usage`、`unieai-invite` —— 正如参考实现是同一个对话框的三个页签。它们需要 ui-settings 的 `settingsPanel` 服务；没有该服务时这三行不存在。
- **浅色模式／深色模式**切换 `ctx.theme`；并且——与在这一行上调用 `preventDefault()` 的参考实现一致——菜单保持打开，以便看到切换生效并撤回。没有主题服务时该行不存在。
- **语言**就是 `ctx.locale` 自己的四种语言，当前语言带对勾。
- **登出**是网关的 `signOut`，它向网关发送登出请求并重新加载。只有存在会话时它才存在；没有网关就没有可登出的对象，因此没有该行。
- **登录**是本菜单相对参考实现的唯一增补，参考实现始终处于已登录状态。这一行过去**就是**登录手势；现在它改为打开菜单，该手势便移入菜单，而不是从栏中消失。

平台管理的缺席理由与上游一致：那一行本就以 `isAdmin` 为条件，而这是个人版，该条件永不成立。没有任何功能被移除。

服务是否存在是**实时**读取的，而非在 apply 时快照。cordis 的激活顺序不受约束，因此晚于本插件激活的面板或主题服务仍须点亮各自的行；在 apply 时读取一次，正是那三行最初消失的原因。

## 「账户」页的头部

本页的开头与 UnieAI 网页版设置页一致：64px 身份标记、18/28/600 的显示名称、其下的方案，以及该产品所印的五格活动条——累计 Token 数、Token 峰值、最长任务时间、当前连续记录、最长连续记录。

第二行只有方案。网页版在那里印 `@handle · 方案`，而本产品没有 handle：没有该字段，没有该路由，没有任何东西能回报一个。本节过去把登录地址塞进那个位置，结果同一个地址在一页上印了两次——一次装扮成 handle，一次作为地址——因此该替代已被移除，地址只保留会话卡片这一个归处。

活动条的数字来自 `UnieAiAccount.activity.stats`，以五个统计 id 为键，且已由供给方格式化——五者单位各异（计数、时长、天数跨度），只有供给方知道自己的数字带哪个单位。未被回报的数字印一个破折号。这也正是该条在包括 `unavailable` 在内的每个状态下都绘制的理由：它展示这个页面**是什么**，同时没有任何一格读起来像账户从未回报过的零。

## Token 活动

活动条之下，是参考资料页所画的同一张贡献式网格：以包含今天的那一周为末尾的 53 个整周，每列一周、每格一天，上方带「每日／每周／累计」切换。「每日」按当天自身的 Token 上色；「每周」按整周之和给该列七格上同一个色；「累计」按占全年总量的进度上色。分级沿用参考实现——前两种模式取账户自身非零值的四分位，第三种取总量的均等五分——因此两侧界面读起来是同一张图，而不是同一个概念的两种方言。

有三处出自本包而非参考实现，每一处都因为参考实现的答案在此不可用：

- **网格以 UTC 构建。** 供给方以 UTC 日为键；若按读者所在时区对齐，格林尼治以西的每一位读者都会看到当天的 Token 落在相邻格里。
- **不使用 `date-fns`。** 整周对齐与 `YYYY-MM-DD` 键不过是十几行 UTC 算术。真正需要语言数据的只有每列下方的月份简称，它由 `Intl` 依当前语言 id 给出——这也是本区块需要知道当前语言的唯一理由——而在运行时没有该语言数据时回退为月份数字。
- **色阶由两个 token 混合而成。** 参考实现用了十个 Tailwind zinc 字面色（每种配色五个）；本仓库不允许任何字面颜色。第 0 级是空格自身的表面，第 4 级是页面的墨色，其间三级是这两者的 `color-mix`——一条表达式即可在两种配色下各自正确地反转。五个百分比本身没有 token：`--dsw-*` 中没有任何名称表达「五级中性色阶」，因此它们是本样式表自己的数字，并如实说明。

网格铺满容器，并在低于 689px（53 列 × 每格可辨识下限 10px）时在自身内部横向滚动，因此窄面板滚动的是网格而不是页面。若供给方回报了活动条却没有序列，本区块用一行文字说明：整年空格读起来像「你什么都没做」，而这与「没有任何回报」是两回事。

名称、头像与方案只出现在该头部，而头部同时也是**更改**前两者的地方。其下的卡片只承载登录地址与退出该会话的出口，因此页面上没有任何一个事实拥有两个归处。

## 在头部就地编辑

不再有独立的「个人资料」卡片。64px 身份标记**就是**更改头像的入口，显示名称则就地变成输入框。

名称旁保留一枚小铅笔，而不是让点击文字本身生效。默默响应点击的头部教不会任何人它可以被点，触屏读者更是永远发现不了——这与身份标记采用常驻角标而非悬停浮层是同一个理由。按下铅笔，名称行便换成输入框、一个「保存」与一个「取消」。

暂存照片打开的是同一份表单。页面上只有一个「保存」，它同时存下这两件事，因此它绝不会在旁边没有对应字段时被画出来；悬在头部之上的保存按钮，附着的是读者看不见的东西。「取消」与供给方接受的保存都会关闭表单并丢弃全部本地编辑，这正是让头部回到已存账号的方式。

文案沿用参考资料表单自身的措辞，逐字取自该产品 `Settings` 消息在四种随附语言中的原文；铅笔的可访问名称「编辑显示名称」是本包自己写的，因为参考实现没有就地编辑器，也就没有给它命过名。

按下身份标记会打开更改头像对话框，先选文件，再展示将被保留的那个正方形，最后确认。除动图 GIF 之外的一切都会在离开页面前按中心裁切为 512px PNG，与参考实现一致——头像以 base64 `data:` URL 传输并存储，未经裁切的手机照片会把数 MB 写进账号行，并在两侧界面此后的每次读取中重复传输。GIF 则整份透传，因为经画布重新编码只会留下其中一帧。可接受的格式沿用产品自己的清单，因此选择器绝不会接受一个保存会拒绝的文件。

头部不保存任何一份已存资料的副本。字段与身份标记都回退到它所渲染的账号，只有真正做出的编辑才会覆盖它们；因此无论保存落在此处还是浏览器中，快照一动即被采纳，而只改名称的保存根本不携带头像字段——缺失正是告诉供给方「保留已存照片」的写法。

校验属于供给方。本包只拒绝提交空白名称，因为该字段必填，就地告知比往返一次更快；其余规则——长度、图片类型、图片编码——都归产品所有，在此再写一份只会做出不同的判断。

## 每个页面在未登录时的样子

`signed-out` 与 `failed` 在这里是寻常状态，而现在有三个页面要各自回答它们。三者都画同一张未连接卡片：页面保留自己的标题，说明它为何是空的，并给出唯一能填满它的动作（「登录」，或覆盖着供给方原话的「重试」；`unavailable` 则说明此版本未内建账号服务，并且不画按钮，因为没有任何东西可供按钮抵达）。

两种替代方案都过不了读者这一关。**把页面从导航中隐去**会挪动刚刚学会它们位置的人所瞄准的那几行，还会弄坏账户菜单：`settingsPanel.open` 在拿到的 id 不存在时会回退到第一个已注册分区，于是「剩余用量」那一行会悄悄打开「账户」页。**把页面留白**更糟——那是在报告一个没有任何额度的账号，而不是没有账号。

「账户」页在这些状态下仍保留身份头部，只是渲染为只读：标记显示人形字符，行文说明尚无人登录，头像入口与名称铅笔都不存在，因为二者都会打开一个「保存」无处可去的表单。活动条仍在，每一格都是破折号。

## 账户网关

供给方是加入 UnieAI 网页产品的桌面 BFF，由持有会话 API key 的宿主代为访问；浏览器侧由某个插件提供 `unieaiAccount` 服务。因此本包在这一侧定义接缝，并如实呈现当前状态。

`UnieAiAccountGateway` 是一对 `getSnapshot`/`subscribe` 加上 `signIn`/`signOut`/`saveProfile`，以及可选的 `sendInvite`。组合方以 `unieaiAccount` cordis 服务提供其一；`apply` 在组合时读取一次，并通过 `internal/service` 采纳后到的那一个，两者都包进 `AccountSource`，后者缓存快照，使多次读取在状态未动时保持同一引用。没有网关时状态恒为 `unavailable` —— 不调用任何端点，不编造身份，不虚构额度数字，写入也如实回报失败，而不是一次从未离开页面的变更。

`saveProfile` 回答 `saved`，或带可选 `reason` 的 `failed`。这样拆分是刻意的：**哪一种**拒绝发生了归供给方所有，因为规则由它执行；措辞归本区块所有，因为保存失败是它自身表单文案中的一行，而它已在四种语言中随附该文案。它能渲染的三个标识是 `name-required`、`avatar-format` 与 `avatar-payload`；若拒绝被标识为别的东西，或根本未被标识，则回退到参考表单的「更新失败，请稍后再试」。`saved` 意味着快照已经携带存下的值，因此表单从不把自己的编辑并入它正在绘制的账号。

`sendInvite` 之所以可选，是因为它是写入，而供给方可能只暴露读取。它回答 `sent`、带三个本区块有措辞的标识之一的 `refused`、部署完全无法发送邀请时的 `unsupported`，或 `failed`。

`UnieAiAccountState` 把 `unavailable` 与 `signed-out` 分开，因为用户可见的差别是真实的：前者表示没有组合任何网关，登录按钮按下去也没有去处，因此不画；后者表示网关存在但没有会话，于是登录正是这个画面最想让你按的动作。它们与 `signed-in` 之间刻意没有中间状态：本产品的登录是宿主服务端渲染的设备码流程，按下「登录」会把浏览器带离单页应用，回来的应用要么已登录要么没有；等待中的姿态在应用内部无法观测，而画出它的那个分支在任何组合里都不可达。

## 邀请

产品的推荐模型是「每个被邀请地址一行」，每行各有自己的一次性邀请码。不存在长期有效的个人邀请链接，因此卡片也不提供：它展示的是账号已积攒的速率限制重置次数、已发出的邀请数量、供给方列出时的那些邀请（每条各带自己的链接与一个复制控件），以及打开撰写对话框的入口。每一部分只在供给方回报时绘制，因此推荐接口调用失败的账号显示的是已到达的部分，而不是一个没人回报过的零余额。

积攒的次数在此**可见但不可使用**。产品把重置次数记在账号上；桌面界面没有任何兑换路由，因此卡片只报告余额，而不提供花掉它的按钮。

### 撰写对话框

撰写一封邀请是一个模态框，而不是页面上的一行：一条头图、一封邀请能换到什么、页面自己的标题与说明、一个地址输入框、一颗发送按钮。它用的是参考设计的框架，填进去的是本产品真正拥有的东西。

这个框架里有三处背后没有数据，每一处都是如实回答而非伪造：

- **没有邀请链接，也没有邀请码。** 写入接口是 `POST /api/desktop/invite`，它接受一个地址；它签发的一次性邀请码属于那封邀请，而不属于账号。此处的个人链接或邀请码只能是编造的，因此对话框两者都不显示 —— 真正存在的链接属于已发出的邀请，列在它背后的页面上。
- **奖励条说明的是比率，而不是一个点数。** `invite.reward` 是本字典已经承载的推荐条款。`UnieAiInvites` 没有任何字段回报奖励**比率** —— `credits` 是已积攒的余额，那是另一个事实，由页面报告 —— 因此奖励条里没有任何数字是从账户算出来的。
- **没有资格条件链接。** 账户契约里没有条款 URL，也就没有东西可供它打开。

在输入框里出现一个说得通的地址（本地部分、`@`、带点的域名）之前，发送一直保持禁用。这是格式上的预检，而不是产品规则的第二份副本：哪些地址可接受、哪一个是账号自己的，仍由供给方裁定，并以 `invalid-email`、`self-invite` 或 `already-invited` 回来。

头图是本包唯一一块固定色板。它在两种调色板下都是同一条品牌蓝色带，上面托着一枚白色方块，因此它取用与调色板无关的 `--dsw-static-deepseek-*` 色阶（该色阶承载 UnieAI 品牌蓝），而不是会把它翻成「白块压深色带」的语义别名。头图以下的一切仍由主题决定。方块画的是邀请自身的主题，而非参考设计里的产品标记：该标记是 `ui-brand-unieai` 提供的品牌 slot 占位者，本包不得对它做值导入，而设置分区也不渲染任何 slot 去够到它。

## 样式

只使用 CSS Modules 与 `--dsw-alias-*` 语义 token。样式表不写任何字面颜色，也不用品牌色：画面上最想让人按的那一颗按钮，其分量来自 `Button` 原语的 `primary` 家族 —— 它解析为中性墨色，与网页产品自己的主按钮完全一致；已用额度条使用 `label-primary`，因为用量条报告的是状态而非动作。填充使用 `bg-module-platform` 而非 `bg-layer-*` —— 浅色调色板中第 1 至 3 层解析为同一个白色，用它上色的表面只有在深色主题下才分得出来。

## Model Experience

无，本包仅贡献浏览器呈现；它读取的账户网关拥有全部请求，此处没有任何内容进入模型。

#### KV Cache effect

无；本包既不组装也不发送供应商请求。

## Known Limitations and Deferred Work

- **仍可能有组合不附带网关** —— `dsh-web-app` 已在本行之前组合 `unieai-account-gateway`，因此出货的桌面版有供给方；省略那一行的组合渲染未连接卡片，那是一个如实的状态，而不是占位。
- **可编辑的只有名称与头像** —— 登录地址与方案都不可改，因为产品也不从这个界面更改它们。
- **头像只能替换，不能移除** —— 参考表单同样不提供移除控件，因此本表单也没有。其下的缝能表达清除（协议上的 `image: null`），而移除按钮会是它唯一的消费者。
- **只有三种拒绝有措辞** —— `name-required`、`avatar-format` 与 `avatar-payload` 渲染为参考表单自己的那几行；其余任何拒绝，以及任何不标识原因的供给方，仍然只显示笼统的「更新失败，请稍后再试」。
- **裁切依赖画布** —— 不提供 2D 绘图上下文的文档无法产出那个正方形，对话框会回报头像保存失败，而不是把未裁切的原图存下。
- **邀请对话框的头图没有产品标记** —— 标记作为 `sidebar.brand.mark` 占位者住在 `ui-brand-unieai` 里，而设置分区没有可用来渲染它的 slot 座位，因此方块改画邀请自身的主题。要补上它，需要一个设置页面够得到的品牌座位。
- **积攒的重置次数无法在此使用** —— 卡片报告余额，因为账号确实有；产品没有向桌面暴露兑换路由，因此没有任何东西可供按钮调用。
- **热力图的五级色阶是本样式表自己的数字** —— 设计平台没有命名任何五级中性色阶，因此那几个把墨色混进空格表面的百分比，是为了在两种配色下保持五级可辨而选定的，并非他人可复用的 token。
- **热力图的格子没有键盘路径** —— 与参考实现一样，一格的日期与 Token 数写在它的 `title` 上，因此可用指针取得而不在 Tab 序列中。网格上方的五项总计以文字承载同一年的数据，其下的月份标尺标为 `aria-hidden`，因为它就是标尺；为 371 个格子安排焦点顺序不值得那些 Tab 停靠点。
- **重置时间与方案名称由供应方预先格式化** —— 本地化由供应方负责，因此切换语言不会重排已经送达的值。
- **两个新页面列在 PERSONAL 导航分组之外** —— `ui-settings-general` 依一份字面 id 清单决定导航分组（`src/client/SettingsRoot.tsx` 中的 `NAV_GROUPS`），其中只点名了 `unieai-account` 与 `general`。未被点名的 id 仍会列出，但排在所有具名分组之后、不带任何标题，因此 `unieai-usage` 与 `unieai-invite` 落在导航末尾，而不是紧挨「账户」。它们的 `order` 值已经相邻且正确；修复只是本包并不拥有的那个包里的一行，而它们的导航图标（同一份映射中的 `navIcon`，对未知 id 回退为设置齿轮）也是同一处调用。
