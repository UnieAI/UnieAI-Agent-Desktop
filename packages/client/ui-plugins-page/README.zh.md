# @unieai/uad-client-ui-plugins-page

[English](README.md) | 中文

**插件**界面：侧边栏「插件」行在框架主区域打开的视图，容纳第一方的 **UnieAI Studio** 条目、产品可安装的**插件目录**、一个**技能**去处、UnieAI 账号的 **Studio MCP** 服务器、本次构建的只读**插件清单**，以及本部署的 **cordis 插件注册表**。

## 为什么要有它

「插件」在这个产品里指两件不同的事，而侧边栏那一行指向了错的那一件。在 UnieAI Copilot 网页版里，「插件」是一个去处：账号安装的组合包与 MCP 服务器。在这个桌面版里，「插件」是设置面板里的 cordis 注册表——真实、有用，但面向开发者。按下侧边栏那一行打开的是第二件事，标签承诺的却是第一件。

现在两者都是这一页上的区块，谁都不独占那个词。做到这件事没有重写任何东西：cordis 界面仍然是 `ui-settings-plugins` 自己的组件、自己的标签页、自己的卡片；它只是从 `settings.section` 这个座位移到本页的 `plugins.page.area` 座位，那是同一种形状的座位，只是换了一个表面。

设置外壳自己的「插件」导航行不必改动就消失了。它只在有 `plugins` 设置分区注册时才绘制，移动之后就没有了——所以两行不可能同时出现，[`ui-settings-general`](../ui-settings-general/README.zh.md) 一行也不用改。

## 它在结构上是什么

一个 `shell.overlay` 条目，也就是框架文档里唯一一个可叠加的 root 座位。那一层横跨整个应用盒子，所以本界面把自己的左边缘按 `--dsh-shell-sidebar-width` 让开——那是 [`ui-layout`](../ui-layout/README.zh.md) 的 `SIDEBAR_WIDTH_PROPERTY`，框架**实际渲染**的栏宽，以内联自定义属性写在框架元素上。于是导航栏在任何宽度下都留着，拖动时留着，窄视口自动折叠时也留着，而它的「插件」行在读者停在这里期间一直是被标记的那一行。从侧边栏抵达的去处必须让侧边栏继续站着：那一行既说明你在哪里，也是你接下来可能去的每一个地方。

本界面仍然自带离开的方式——chrome 里的关闭控件、界面上任意位置的 Esc，以及侧边栏那一行本身（它是开关）。那一行是参考设计自己的返回方式；关闭控件之所以存在，是因为它旁边的会话行会在本界面**底下**切换会话，而不会把它关掉。

它声明一个孔 `plugins.page.area`：一个 root 作用域的 list，所有者不提供任何东西，所以区块自己画标题、自己画引言、自己画正文。要在这一页加一个区块是一次注册，而不是改这里的代码。本包以 entry id `unieai-studio` 在 order -20 注册 UnieAI Studio 条目，以 `unieai-directory` 在 order -10 注册插件目录，以 `studio-mcp` 与 `skills` 在 order 0 注册 Studio MCP 与技能区块；[`ui-settings-plugin-inventory`](../ui-settings-plugin-inventory/README.zh.md) 以 id `plugin-directory` 在 order 5 注册 cordis 清单；`ui-settings-plugins` 在 order 10 注册 cordis 注册表。这两个 id 长得很像，必须保持互不相同：一个 list slot 里出现两个同 id 的条目会直接拒绝加载，而不是互相遮蔽，那会让整个应用在启动时挂掉。

本界面拥有唯一一条阅读栏宽，居中、980px，每个区块都继承它。它定在界面这一层而不是定在某个区块里：一个区块自己居中、邻居却铺满整宽，会让同一个界面出现两条栏边。主区域本身仍然是全宽的——这是一个去处，不是对话框——而 chrome 那一行（左边是去处药丸，右边是重新读取、配置与关闭）坐在阅读栏之外，因为它属于界面而不属于正文。

## 三个去处，两个在药丸条上

每个占位者各自是一个去处，把它们叠成一页，会让目录的 22 行和 Loader 的 128 行首尾相接，而没有任何东西说明它们是不同种类的东西。一次只渲染一个去处，通过 `renderSlot(..., { only: id })` 按 entry id 取用。

其中两个是读者会**浏览**的地方，所以它们是左上角的药丸分页：插件目录，以及技能。第三个说的是这个部署**已经是什么**，而不是还能加什么——账号已连接的 MCP 服务器、Loader 的清单、本次构建的 cordis 配置，按 `order` 叠在一起——所以它挂在右上角的齿轮上，也就是参考设计放配置的位置；齿轮在自己的去处显示时会自己标记自己，因为没有药丸能标记它。再按一次就回来。

「已加载模块」这个区块**默认关闭**（`showLoadedModules`，一个部署在自己的 patch 层里设定的 `Config` 字段）。那上面没有任何东西可以操作：主机的清单服务是只读的，无法启用、停用、新增或移除任何东西。打开「插件」的读者要找的是自己能安装什么，而一列他碰不到的引擎零件、还用着相近的词，读起来像是一个坏掉的控件而不是一份报告。这也是它叫「已加载模块」而不是「本机插件」的原因：在这里，「插件」这个词已经指可安装的那一种。

去处表写在界面组件里，点名了别的包的 entry id，这是这个界面唯一知道自己占位者的地方。这种耦合是刻意的，并且有一半有闸门看着：`plugins.page.area` 不带每个条目的标签，泛用的分页条没有东西可写在自己身上；而一个测试断言**本包**注册的每一个区块都恰好被一个去处列出——新增的区块若忘了给去处，会在那里失败，而不是根本不渲染。来自别的包的那两个 id（`plugin-directory`、`cordis-plugins`）在这个闸门够不到的地方。

## UnieAI Studio：这一页唯一一个被写死、而不是被读出来的条目

这个界面上的其它东西都是线上的东西。目录渲染 `/auth/plugins` 列出的内容，Studio MCP 区块渲染 `/auth/mcp` 列出的内容，两个组件都不点名任何一个插件——写死一行等于本包断言某个东西存在于一份属于产品的目录里。

**UnieAI Studio 是刻意的例外，而被写死的只有它的存在。** 它不是一行目录条目：它是本产品自己的账号绑定，正是它提供 Studio 的模型目录、账号自己的 runtime key，以及本页在下方已经画出来的那些 Studio MCP 工具。对任何账号来说，这条绑定要么存在要么不存在，在每一种部署里都如此，所以写下这个条目并没有对别人的目录断言任何事情。它*显示*的一切仍然是读来的：是否已绑定、有哪些工具、乃至究竟有没有账号，全都来自 Studio MCP 区块所绑定的同一个 `StudioMcpSource`——同一个 source 对象注入两个条目，所以两者永远不可能各说各话。

**「已绑定」由产品自己的回答决定，而不是某个旗标。** `/auth/mcp` 转发 `GET /api/desktop/mcp`，只有持有 Studio 绑定的账号才会在里面拿到 id 为 `unieai-studio` 的服务器。所以那一行的存在*就是*绑定本身，而它在一份**已落定**的清单里缺席，意味着未绑定，而不是失败——这正是 `unbound` 只从 `ready` 推导出来的原因，而四种不带清单的读数（正在读取、没有会话、没有 MCP 路由、读不到）各自保留自己的名字与自己的句子。未登录的桌面端既不是已绑定也不是未绑定，并且会直说。

**动作只在一种读数下出现。** 已绑定时画出「已绑定」这个词，以及账号自己那台服务器所报告的工具名；未绑定时画出**綁定** / Bind。未登录时改为请对方先登录，因为绑定是一条账号链接，按下去只会落到登录页。读取失败时给出重试，而这四种里也只有它是重试能修好的。

绑定本身完全发生在网页产品上——`components/settings/studio-link-card.tsx` 对 Studio 跑一次 OAuth device grant——所以这个动作是一个 `<a target="_blank">`，指向产品自己的设置页面，并深链到承载绑定卡片的「个人资料」分页。这个 URL 目前还无从得知什么，见 [Known Limitations](#known-limitations-and-deferred-work)。

标记是一张 754 字节的像素风 PNG，在 `studio-entry.ts` 里以 `data:` URI 内联。之所以内联而不是去取：客户端 bundle 的纯度闸门禁止本包为运行期资源伸手到包外，而且桌面端会在离线状态下面对本地 harness 跑——远程图片恰好会在网络本身出问题时裂开。它画在 40px 的方块里并带 `image-rendering: pixelated`，因为在那个尺寸下，任何默认的平滑滤镜都会把源图一像素宽的边缘糊成灰边。

## 插件目录：把产品的目录变成可以挑选的东西

目录回答的是「我可以加什么」，这和 cordis 清单的「加载了什么」是两个问题，两者要的排版正好相反。清单是给维护这个部署的人读的，要的是密度和标识符；目录是给正在做决定的人读的，要的是名字、一句他自己语言的话，和一个控件。所以整个区块自上而下读起来像一个不断收窄的问题：铺满栏宽的搜索框，然后是这个账号已经装了什么（一排 44px 的标记），然后是筛选钮，然后是目录本身、两行一列——每一行是一个标记、一个名字、一句话，和一个控件。没装的时候，那个控件就是实心药丸上的「安装」二字；装了之后唯一剩下的动作是移除，而让移除在每一行读者已经选过的行上敞着，等于在邀请他撤销，所以它折进参考设计画的 `…` 溢出菜单里。

行来自 `/auth/plugins`，这个构建里没有内置任何一条：产品新增的插件会在下一次读取时出现，不需要重新发布桌面版。分组也是产品的——`category` 随每一行从插件自己的 manifest 过来，出现几个值就画几个标题。这里刻意没有「精选」：一个背后没有依据的编辑分组，等于本包擅自主张目录从未做过的判断。manifest 没有指定分类的行会收在最后一个标题下，而那个词是字典键、不是来自线上的值，因为「manifest 没写」和「产品就是归在其他」必须能分辨。

这一排筛选钮站的正是参考设计放「公开／个人」那一对的位置。**线上没有任何字段能区分这两者**，所以站在那个位置上的是目录真正答得出来的东西：全部、这个账号已安装的、以及出现过的每个发行方各一个钮。发行方钮由行推导而来，所以产品明天新增的发行方不需要发版就会有自己的钮；钮上只站两个，其余折进「更多」，因为超过三个这一排就会折成两行，不再读作同一个控件。被选中的钮永远站着，即使它排在折叠线之外：看不见的筛选是关不掉的筛选。

写入不会自己翻转那一行。什么叫已安装是产品说了算——绑定了哪个版本、策略有没有降级这次请求——所以安装之后会重新读取目录，行随回答而动。`canInstall` 与行并列上报而不是挂在行上，因为它是读者的属性：免费账号看得见整个目录，却一个也装不了。

## 技能：这个部署真正提供的东西

技能去处列出这个部署会交给模型的每一个技能，按文件所在的位置分组，每一行带上文件自己的路径。

**按来源分组，是因为来源决定一个人能对它做什么。** 自己写的可以自己改；项目提供的属于那个仓库、随仓库走；本次构建自带的根本不是他的。`SkillSummary.source` 带的是来源家族，其中两类还带上被找到的目录——所以 `user:/home/p/.dsh/skills` 与 `user` 在这里是同一个标题，而不是一整面路径。本构建认不出来的来源会单独归到最后一个标题下，而不是被丢掉。

**路径写在行上，是因为两个同名技能只会引出这一个问题。** 一个个人的 `review` 盖住项目的 `review`，在一串名字里长得一模一样；写出文件才说得清一轮对话将要读的是哪一个。宿主打得开的时候，行上还给一个打开：`host.openPath` 把文件交给这个人系统上负责 `.md` 的程序，也就是他的编辑器。

### 它就是一轮对话拿到的那份目录，而不是对同几个目录的第二次读取

`skill.catalog`（`packages/host/apiproxy/src/api/skills.ts`）是 root 作用域的：它不收 `sessionId`，因为这个界面有没有会话都能打开。它的答案来自向本部署的**常驻 preset 作用域**——[`agent-presets`](../../preset/agent-presets/README.zh.md) 的 `standingService('skills')`——要一份快照，那正是一轮对话会去问的同一个注册表，经由同一批已挂载的 provider 发现。

这件事比听起来重要。技能发现是透过 `ctx.fs` 读文件的，而是哪一个 `ctx.fs`，取决于会话指向哪台机器；一条用 `node:fs` 走目录的路由，会列出这台电脑上的技能，而同一时间跑在远端机器上的那一轮读到的是那台机器的。去问常驻作用域，页面与模型就不可能对「有哪些技能」给出不同答案。

**发现是异步的，所以这条路由会等一个已经定下来的答案。** 只要还有 provider 在读，`snapshot()` 就报 `complete: false`；而对「有哪些技能」诚实的回答，不是一份过一会儿会悄悄补齐的半截清单。这条路由会重读到快照定下来为止，最多一秒；仍未定下来就把手上有的送出去——之所以有上限，是因为一台慢的远端机器上的目录不该把这一页无限期地拖着。

### 它只列，不写

这里没有新增、编辑、改名或删除的控件，这是设计，不是缺口。一个技能就是一个带 frontmatter 的 Markdown 文件；而本来就很会写文件的，是这个人自己的编辑器和代理——技能也正是这样做出来的：在对话里说一声，本次构建自带的 `skill-creator` 技能会告诉代理文件放哪里、frontmatter 该写什么。区块用结尾的一句话说明这件事，而不是画一个「新增」按钮，去打开一个还不如它所取代的东西的表单。

读取失败时，上一份目录留在画面上，宿主自己的那句话写在它上面。一会儿之前送出来的那份，仍然是任何人手上最好的答案；把清单清空，会把一次断线变成「你没有任何技能」。

## Studio MCP：列出账号已连接的服务器

这个区块通过登录网关读 `GET /auth/mcp`，方式与 [`ui-unieai-providers`](../ui-unieai-providers/README.zh.md) 读 `/auth/providers` 相同。网关转发产品的 `GET /api/desktop/mcp`；认证该接口的 API key 存在主机端网关的会话表里，绝不能到达页面，所以浏览器问主机，主机问产品。

回来的东西只是一份清单：`{ servers: [{ id, label, origin, expiresAt, tools }] }`，其中 `tools` 是一串名字。它公开服务器的**来源地址**，从不给出完整 URL，也**不带令牌**——这是刻意的：远程 MCP 的 URL 常在路径或查询串里夹带凭证，而抵达产品的 bearer 留在主机端。因此这个区块画的是名称、来源地址与工具清单，不提供安装、连接、编辑或删除控件：浏览器根本没有可以拨接的东西，而做不到的控件不该被画出来。新增、修改与删除都在 UnieAI Studio 里进行，区块也把这句话写了出来。

`expiresAt` 在线上，而这里刻意把它丢掉。它描述的是**主机**那份令牌还能用多久；浏览器从不持有那份令牌，知道它何时失效也不会让这一页多出任何可做的动作。用它做倒计时或刷新按钮，只是替别人的时钟做装饰。

`StudioMcpRow` 没有 `url` 也没有 `headers` 成员，而且读取器是按字段名逐个取值，而不是展开线上对象。两者都是刻意的，说的是同一个保证：如果将来的主机开始送凭证，在有人编辑这个类型、读到这一段之前，它既进不了状态也进不了 DOM。除了类型之外，还有一个测试在渲染出的 DOM 上断言同一件事。

### 必须保持为四个的四种回答

- **404 是 `unsupported`。** 比该路由更早的部署根本不提供 MCP 界面，告诉读者「读取失败」会暗示重试有意义。它没有意义，所以那里不画重试。
- **401，以及网关自己的 signed-out 信封，都是 `signed-out`。** 还没有账号可以为它列服务器。
- **5xx、连不上的主机，或本版本读不懂的响应体，都是 `failed`。** 这是唯一能靠重试解决的回答，也是唯一提供重试控件的回答。
- **`{servers: []}` 是有回答、但列表为空的 `ready`。** 那是关于一个真实账号的真实回答，用文字说出来，而不是画成一片空白。

一份其实意味着「我们根本没问」的空列表，正是这个区块要避免的失败模式。清单是靠 `servers` 数组认出来的，而不是靠信封标签，所以产品自己的 `{servers: []}` 与网关的 `{status: "signed-in", servers}` 在这里是同一个回答。

### 工具是单位，服务器是分类

读者来这里是要弄清楚自己有哪些工具。所以拿到卡片的是工具，而服务器是这些卡片所在的标题——名称、旁边的来源地址，底下一条细线。服务器不再是一个自己的方框：把它装进方框，等于在页面已经框起来的内容外面再叠一层边框，还把工具清单——也就是答案——挤进一口窄井里。也不再有上限。工具清单报告多少个工具就画多少张卡片，因为一旦设限，「这台服务器给我什么」就又变回一个数字。

**服务器之所以是分类，是因为它是唯一真实存在的分组。** 线上契约每台服务器报告一个标签与一个来源地址，每个工具报告一个名字。更细的分组只能从名字里切出来——`studio_kb_*` 对 `studio_sql_*`——而那是某一台服务器碰巧遵守的命名惯例，不是它发布的事实。同一条规则会把 Notion 清单里的 `search` 与 `fetch` 切成两个各含一项的分类，或者把整份清单倒进一个「其他」桶里。切分冒充分类法，在用户眼里读起来就是事实，而这一份只是猜测。

**卡片需要一句说明，而主机现在还不送。** `lib/studio/mcp-tools.ts` 为每个 Studio 工具都写了描述；`lib/desktop/mcp.ts` 把清单压成 `STUDIO_MCP_TOOLS.map((tool) => tool.name)`，网关的 `McpServerView` 又把该字段定为 `string[]`，两跳都把它丢了。这里的 `StudioMcpTool` 带有 `description`，并且两种线上形状都读得懂——裸名字，或 `{name, description}`——所以主机开始转发的那一天说明就会出现，中间不需要再发一次页面。在那之前，卡片就只有名字：本包不发明描述，也不画「暂无描述」的占位行，因为一句关于主机沉默的话，比就此打住说得更少。

## 文案

网页版已经发布过的每一行文字，都逐字取自它的 `messages/{en,zh-tw,zh-cn,ja}.json`，来源命名空间与键名标注在 [`src/client/locales.ts`](src/client/locales.ts) 每一行旁边。四个出货语言都有完整字典；本包自己的措辞只有两类：网页不可能处于的状态——没有会话、部署比 MCP 路由更早、列表仍在读取——以及为未命名服务器与未提供来源地址各写的那一行。刻意不为「未报告描述的工具」准备任何键。

## 样式

只用 CSS Modules 与语义化的 `--dsw-alias-*` token，没有字面颜色、没有兜底值、没有品牌色。导航行自行绘制外壳的行几何，因为 `sidebar.nav.action` 不为它的占用者保存任何状态。服务器来源地址与工具名都以代码字体排版，因为两者都是人们一个字符一个字符比对、或者要照着敲的值。

工具网格是 `repeat(auto-fill, minmax(min(232px, 100%), 1fr))`。`min(…, 100%)` 这个下限是受力构件，不是装饰：页面占满整个框架宽度，而一旦框架比一个轨道还窄，裸写 `232px` 的下限就会撑破容器，把整页在 390px 下推得横向滚动。

工具卡片用填充而非描边，底色取 `--dsw-alias-bg-module-platform`，圆角取 `--dsw-radius-control` 而不是 `--dsw-radius-card`——在这个尺寸上，卡片圆角看起来就是一团圆疙瘩。`--dsw-alias-bg-layer-1` 在这一页不能用来做卡片：浅色主题把它解析成与页面所涂的 `--dsw-alias-bg-base` 同一个值，因此只靠填充的卡片会在深色下存在、在浅色下消失。这两个选择都有测试对着样式表断言。

## Model Experience

无：本包只贡献浏览器呈现，两个区块都不会进入模型请求。

无；本包不组装也不发送任何请求。

## Known Limitations and Deferred Work

- **绑定动作永远指向 `https://agent.unieai.com`，即使某个部署把 `productUrl` 指到了别处。** 路径是确认过的——产品的设置页面把绑定卡片放在「个人资料」分页上，而 `settings-client.tsx` 用 hash 深链分页——但来源地址是一个常量，因为浏览器可以调用的路由里没有任何一条会报告已配置的产品来源地址。`/auth/mcp` 只会公布账号已经拥有的服务器的来源地址，而那按定义就不是这个动作所面对的未绑定账号。要闭合这一点，需要网关把自己的 `productUrl` 公布给浏览器，那是 `unieai-web-gate` 的改动，不是本页的改动；自架的 copilot-v2（docs/unieai-development.zh.md）目前会被这一条链接送到公开产品上。
- **能列出不等于能连接，这个桌面版仍然连不上。** 回答刻意只带来源地址，不带接口地址与凭证；存储的请求头与 OAuth bearer 在服务端解密、从不投射给任何客户端。因此连接要么需要产品托管、桌面版能用自己的密钥拨接的中继——那正是 [`@unieai/uad-mcp-client`](../../mcp/mcp-client/README.zh.md) 已经支持的形态，一个带 `authorization` 请求头的 `streamable-http` 服务器——要么需要决定把 MCP 凭证送到笔记本上，而那与这个桌面版处理其他每一份凭证的方式相违。两者都在本包之外。
- **本仓库没有任何东西去挂载列出来的服务器。** `mcp-client` 每个静态配置行挂载一个服务器，名称在编译期就唯一；要把活的列表变成活的连接，需要一个随列表变动挂载与释放插件的监督者，而本仓库没有这个组件。在它出现之前，这个区块是通往账号 Studio 的一扇窗，而不是某一轮对话的工具来源。
- **比该路由更早的部署仍然显示 `unsupported`，也仍然每次打开页面留下一个 404。** 这个状态与它的文案正是为那种部署保留的。控制台那一行，是去问一个可能不存在的路由所付的可见代价；而正是「去问」让这个界面在路由上线那天自动亮起来，浏览器端不必再改。
- **工具卡片没有描述，因为主机那两跳把它丢了。** 产品在 `lib/studio/mcp-tools.ts` 里为每个 Studio 工具都写了一句，而它在送到这里的路上被丢了两次：`lib/desktop/mcp.ts` 发布的是 `tools: STUDIO_MCP_TOOLS.map((tool) => tool.name)`，`web-gate` 的 `McpServerView.tools` 又被定为 `string[]` 并由 `readTools` 原样拷贝。要把卡片填满，需要把产品路由与网关的 grant/view 这一对都改成携带 `{name, description}`，而这两个文件都不属于本包。浏览器这一半已经写完并有测试：带描述的条目会渲染，裸名字仍然读得懂，而在此期间这里不会编造任何一句话。
- **区块分不出服务器是启用还是停用。** 面向浏览器的契约不报告启用标志，也不报告归属范围，所以行里两者都不显示，而不是去猜；需要这个区分的读者请到 Studio 上看。
- **目前还没有产品提供 `/auth/plugins`，所以在现有的每个部署里目录都读作 `unsupported`。** 浏览器这一半已经完成，并且是对着目录自己的行测过的；缺的是产品端的 `/api/desktop/plugins`，它今天回 404，而 `/api/desktop/mcp` 和其余几条都回 401。资料源读取的回应字段是固定的，写在 `directory-source.ts` 里，所以把那条路由上线是剩下的唯一一步。
- **目录显示的插件名字就是目录里存的样子。** 大部分是 slug 形式（`gl-reconciler`、`kyc-screener`），只有 `text-transform: capitalize` 把它们和标识符区分开，于是渲染成 `Gl-Reconciler`。在浏览器里重写它们等于本包替别人的产品编名字；该修的地方在目录资料。
- **目录里没有任何发行方上传过标记，所以每一行都画首字母。** `iconUrl` 有就会读、就会渲染——产品那边确实有这个字段，存成 `NOT NULL DEFAULT ''`——而首字母方块对每一行都是中性的，这是刻意的：一个插件一个颜色，等于本包替别人的产品发明品牌识别。
- **本界面是靠自己让开来坐在侧边栏旁边的，而不是占了一个主区域座位。** 框架没有为「只是主区域」声明 slot：`conversation` 是 ui-conversation 占着的 `single` 座位，占了它就等于删掉整个对话界面。所以本界面仍然是 `shell.overlay` 的占位者，只是按框架发布的栏宽让开自己的左边缘。可见的代价是侧边栏拖动条：它跨在栏边界上，打开时靠内的那一半会被本界面盖住。
- **参考设计的「新增 ⌄」控件没有画，因为这台主机上没有任何东西可以新增。** 网关没有任何创建插件的路由，而 Studio MCP 区块按设计就是只读的——服务器在 UnieAI Studio 里新增。一个每一项都会拒绝的菜单按钮比没有按钮更糟，所以 chrome 上放的是重新读取、配置与关闭。
- **参考设计里「已安装」标题旁的那个小齿轮没有画。** 它会通往 chrome 上齿轮已经通往的同一个配置去处，而同一个屏幕上为同一个去处放两个控件，是一个背后没有差别的选择。
- **参考设计的「公开／个人」分段控件没有画。** `DirectoryRow` 不带可见性或归属字段，资料源读取的回应里也没有；那个位置上的筛选钮给出的是目录答得出来的东西。
- **技能去处只读，新增一个是一段对话而不是一个控件。** 这里不写任何 `SKILL.md`，所以想要一个新技能的人去请代理写，再回到这份清单。一个表单得自己拥有 frontmatter 规则、目录选择与校验，而这些 `skill-creator` 技能已经用文字说清楚了；表单只会让这些规则多一个可能出错的地方。
- **目录是进来时读一次，不是持续盯着。** 技能是在 Rabi 之外被编辑的文件，底下没有任何东西发布变更流，所以在这个去处开着的时候写下的技能，要按「重新读取」才会出现。要盯着它，就得在会话所指的那台机器上、为每个技能目录开一个文件监看，那是比这一页该开的更大的接缝。
- **载入失败的技能是缺席，而不是被报告。** 注册表的快照带的是解析成功的那些；一个 frontmatter 坏掉的 `SKILL.md` 就是不在里面，而这一页分不出它和一个根本没人写过的文件。要显示出来，需要技能服务报告自己拒绝了什么，而它今天不报告。
