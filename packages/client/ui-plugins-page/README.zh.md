# @deepseek-ai/dsh-client-ui-plugins-page

[English](README.md) | 中文

**插件**页面：侧边栏「插件」行打开的独立页面，把 UnieAI 账号的 **Studio MCP** 服务器、本次构建的只读**插件目录**与本部署的 **cordis 插件注册表**放成同一页上的三个区块。

## 为什么要有它

「插件」在这个产品里指两件不同的事，而侧边栏那一行指向了错的那一件。在 UnieAI Copilot 网页版里，「插件」是一个去处：账号安装的组合包与 MCP 服务器。在这个桌面版里，「插件」是设置面板里的 cordis 注册表——真实、有用，但面向开发者。按下侧边栏那一行打开的是第二件事，标签承诺的却是第一件。

现在两者都是这一页上的区块，谁都不独占那个词。做到这件事没有重写任何东西：cordis 界面仍然是 `ui-settings-plugins` 自己的组件、自己的标签页、自己的卡片；它只是从 `settings.section` 这个座位移到本页的 `plugins.page.area` 座位，那是同一种形状的座位，只是换了一个表面。

设置外壳自己的「插件」导航行不必改动就消失了。它只在有 `plugins` 设置分区注册时才绘制，移动之后就没有了——所以两行不可能同时出现，[`ui-settings-general`](../ui-settings-general/README.zh.md) 一行也不用改。

## 它在结构上是什么

一个 `shell.overlay` 条目，也就是外壳文档里为「属于你自己的表面」指定的座位。页面在整个框架上涂基底底色，并自带离开的方式——页头控件，以及页面上任意位置的 Esc。因为横跨整个框架，打开时会盖住侧边栏；要让页面落在栏位旁边，需要布局所有者今天并未声明的页面座位。

它声明一个孔 `plugins.page.area`：一个 root 作用域的 list，所有者不提供任何东西，所以区块自己画标题、自己画引言、自己画正文。要在这一页加一个区块是一次注册，而不是改这里的代码。本包以 entry id `unieai-directory` 在 order -10 注册插件目录，以 `studio-mcp` 在 order 0 注册 Studio MCP；[`ui-settings-plugin-inventory`](../ui-settings-plugin-inventory/README.zh.md) 以 id `plugin-directory` 在 order 5 注册 cordis 清单；`ui-settings-plugins` 在 order 10 注册 cordis 注册表。这两个 id 长得很像，必须保持互不相同：一个 list slot 里出现两个同 id 的条目会直接拒绝加载，而不是互相遮蔽，那会让整个应用在启动时挂掉。

这一页拥有唯一一条阅读栏宽，居中、720px，每个区块都继承它。它定在页面这一层而不是定在某个区块里：一个区块自己居中、邻居却铺满整宽，会让同一页出现两条栏边。框架本身仍然是全宽的——这一页是一个去处，不是对话框——而返回控件坐在框架自己的左上角、在阅读栏之外，因为它属于窗口而不属于正文。

## 三个分页，不是一叠区块

三个占位者各自是一个去处——账号可以安装什么、账号已经连接了什么、这个构建加载了什么——把它们叠成一页，会让目录的 22 行和 Loader 的 128 行首尾相接，而没有任何东西说明它们是不同种类的东西。

分页表写在页面里，点名了别的包的 entry id，这是这一页唯一知道自己占位者的地方。这种耦合是刻意的，并且有闸门看着：`plugins.page.area` 不带每个条目的标签，泛用的分页条没有东西可写在自己身上；而一个测试断言这张表覆盖了实际注册的每一个 id——新增的区块若忘了给分页，会在那里失败，而不是从页面上消失。

## 插件目录：把产品的目录变成可以挑选的东西

目录回答的是「我可以加什么」，这和 cordis 清单的「加载了什么」是两个问题，两者要的排版正好相反。清单是给维护这个部署的人读的，要的是密度和标识符；目录是给正在做决定的人读的，要的是名字、一句他自己语言的话，和一个控件。所以它的行在页面的栏宽里两个一行，每一行带一个标记、一个名字、一句话，和单独一个 `+` / `−`。

行来自 `/auth/plugins`，这个构建里没有内置任何一条：产品新增的插件会在下一次读取时出现，不需要重新发布桌面版。分组也是产品的——`category` 随每一行从插件自己的 manifest 过来，出现几个值就画几个标题。这里刻意没有「精选」：一个背后没有依据的编辑分组，等于本包擅自主张目录从未做过的判断。manifest 没有指定分类的行会收在最后一个标题下，而那个词是字典键、不是来自线上的值，因为「manifest 没写」和「产品就是归在其他」必须能分辨。

发行方筛选钮由行推导而来，所以产品明天新增的发行方不需要发版就会有自己的钮。钮上只站两个，其余折进「更多」——筛选钮和搜索框共用一行，而一个每个插件都有自己发行方的目录，会把读者第一个要伸手去按的搜索框挤到单独一行。被选中的钮永远站在行上，即使它排在折叠线之外：看不见的筛选是关不掉的筛选。

写入不会自己翻转那一行。什么叫已安装是产品说了算——绑定了哪个版本、策略有没有降级这次请求——所以安装之后会重新读取目录，行随回答而动。`canInstall` 与行并列上报而不是挂在行上，因为它是读者的属性：免费账号看得见整个目录，却一个也装不了。

## Studio MCP：列出账号已连接的服务器

这个区块通过登录网关读 `GET /auth/mcp`，方式与 [`ui-unieai-providers`](../ui-unieai-providers/README.zh.md) 读 `/auth/providers` 相同。网关转发产品的 `GET /api/desktop/mcp`；认证该接口的 API key 存在主机端网关的会话表里，绝不能到达页面，所以浏览器问主机，主机问产品。

回来的东西只是一份清单：`{ servers: [{ id, label, origin, expiresAt, tools }] }`，其中 `tools` 是一串名字。它公开服务器的**来源地址**，从不给出完整 URL，也**不带令牌**——这是刻意的：远程 MCP 的 URL 常在路径或查询串里夹带凭证，而抵达产品的 bearer 留在主机端。因此这个区块画的是名称、来源地址与工具清单，不提供安装、连接、编辑或删除控件：浏览器根本没有可以拨接的东西，而做不到的控件不该被画出来。新增、修改与删除都在 UnieAI Studio 里进行，区块也把这句话写了出来。

`expiresAt` 在线上，而这里刻意把它丢掉。它描述的是**主机**那份令牌还能用多久；浏览器从不持有那份令牌，知道它何时失效也不会让这一页多出任何可做的动作。用它做倒计时或刷新按钮，只是替别人的时钟做装饰。

`StudioMcpRow` 没有 `url` 也没有 `headers` 成员，而且读取器是按字段名逐个取值，而不是展开线上对象。两者都是刻意的，说的是同一个保证：如果将来的主机开始送凭证，在有人编辑这个类型、读到这一段之前，它既进不了状态也进不了 DOM。除了类型之外，还有一个测试在渲染出的 DOM 上断言同一件事。

### 必须保持为四个的四种回答

- **404 是 `unsupported`。** 比该路由更早的部署根本不提供 MCP 界面，告诉读者「读取失败」会暗示重试有意义。它没有意义，所以那里不画重试。
- **401，以及网关自己的 signed-out 信封，都是 `signed-out`。** 还没有账号可以为它列服务器。
- **5xx、连不上的主机，或本版本读不懂的响应体，都是 `failed`。** 这是唯一能靠重试解决的回答，也是唯一提供重试控件的回答。
- **`{servers: []}` 是有回答、但列表为空的 `ready`。** 那是关于一个真实账号的真实回答，用文字说出来，而不是画成一片空白。

一份其实意味着「我们根本没问」的空列表，正是这个区块要避免的失败模式。清单是靠 `servers` 数组认出来的，而不是靠信封标签，所以产品自己的 `{servers: []}` 与网关的 `{status: "signed-in", servers}` 在这里是同一个回答。

### 工具是单位，服务器是分类

读者来这里是要弄清楚自己有哪些工具。所以拿到卡片的是工具，而服务器是这些卡片所在的标题——名称、旁边的来源地址，底下一条细线。服务器不再是一个自己的方框：把它装进方框，等于在页面已经框起来的内容外面再叠一层边框，还把工具清单——也就是答案——挤进一口窄井里。也不再有上限。工具清单报告多少个工具就画多少张卡片，因为一旦设限，「这台服务器给我什么」就又变回一个数字。

**服务器之所以是分类，是因为它是唯一真实存在的分组。** 线上契约每台服务器报告一个标签与一个来源地址，每个工具报告一个名字。更细的分组只能从名字里切出来——`studio_kb_*` 对 `studio_sql_*`——而那是某一台服务器碰巧遵守的命名惯例，不是它发布的事实。同一条规则会把 Notion 清单里的 `search` 与 `fetch` 切成两个各含一项的分类，或者把整份清单倒进一个「其他」桶里。切分冒充分类法，在用户眼里读起来就是事实，而这一份只是猜测。

**卡片需要一句说明，而主机现在还不送。** `lib/studio/mcp-tools.ts` 为每个 Studio 工具都写了描述；`lib/desktop/mcp.ts` 把清单压成 `STUDIO_MCP_TOOLS.map((tool) => tool.name)`，网关的 `McpServerView` 又把该字段定为 `string[]`，两跳都把它丢了。这里的 `StudioMcpTool` 带有 `description`，并且两种线上形状都读得懂——裸名字，或 `{name, description}`——所以主机开始转发的那一天说明就会出现，中间不需要再发一次页面。在那之前，卡片就只有名字：本包不发明描述，也不画「暂无描述」的占位行，因为一句关于主机沉默的话，比就此打住说得更少。

## 文案

网页版已经发布过的每一行文字，都逐字取自它的 `messages/{en,zh-tw,zh-cn,ja}.json`，来源命名空间与键名标注在 [`src/client/locales.ts`](src/client/locales.ts) 每一行旁边。四个出货语言都有完整字典；本包自己的措辞只有两类：网页不可能处于的状态——没有会话、部署比 MCP 路由更早、列表仍在读取——以及为未命名服务器与未提供来源地址各写的那一行。刻意不为「未报告描述的工具」准备任何键。

## 样式

只用 CSS Modules 与语义化的 `--dsw-alias-*` token，没有字面颜色、没有兜底值、没有品牌色。导航行自行绘制外壳的行几何，因为 `sidebar.nav.action` 不为它的占用者保存任何状态。服务器来源地址与工具名都以代码字体排版，因为两者都是人们一个字符一个字符比对、或者要照着敲的值。

工具网格是 `repeat(auto-fill, minmax(min(232px, 100%), 1fr))`。`min(…, 100%)` 这个下限是受力构件，不是装饰：页面占满整个框架宽度，而一旦框架比一个轨道还窄，裸写 `232px` 的下限就会撑破容器，把整页在 390px 下推得横向滚动。

工具卡片用填充而非描边，底色取 `--dsw-alias-bg-module-platform`，圆角取 `--dsw-radius-control` 而不是 `--dsw-radius-card`——在这个尺寸上，卡片圆角看起来就是一团圆疙瘩。`--dsw-alias-bg-layer-1` 在这一页不能用来做卡片：浅色主题把它解析成与页面所涂的 `--dsw-alias-bg-base` 同一个值，因此只靠填充的卡片会在深色下存在、在浅色下消失。这两个选择都有测试对着样式表断言。

## Known Limitations and Deferred Work

- **能列出不等于能连接，这个桌面版仍然连不上。** 回答刻意只带来源地址，不带接口地址与凭证；存储的请求头与 OAuth bearer 在服务端解密、从不投射给任何客户端。因此连接要么需要产品托管、桌面版能用自己的密钥拨接的中继——那正是 [`@deepseek-ai/dsh-mcp-client`](../../mcp/mcp-client/README.zh.md) 已经支持的形态，一个带 `authorization` 请求头的 `streamable-http` 服务器——要么需要决定把 MCP 凭证送到笔记本上，而那与这个桌面版处理其他每一份凭证的方式相违。两者都在本包之外。
- **本仓库没有任何东西去挂载列出来的服务器。** `mcp-client` 每个静态配置行挂载一个服务器，名称在编译期就唯一；要把活的列表变成活的连接，需要一个随列表变动挂载与释放插件的监督者，而本仓库没有这个组件。在它出现之前，这个区块是通往账号 Studio 的一扇窗，而不是某一轮对话的工具来源。
- **比该路由更早的部署仍然显示 `unsupported`，也仍然每次打开页面留下一个 404。** 这个状态与它的文案正是为那种部署保留的。控制台那一行，是去问一个可能不存在的路由所付的可见代价；而正是「去问」让这个界面在路由上线那天自动亮起来，浏览器端不必再改。
- **工具卡片没有描述，因为主机那两跳把它丢了。** 产品在 `lib/studio/mcp-tools.ts` 里为每个 Studio 工具都写了一句，而它在送到这里的路上被丢了两次：`lib/desktop/mcp.ts` 发布的是 `tools: STUDIO_MCP_TOOLS.map((tool) => tool.name)`，`web-gate` 的 `McpServerView.tools` 又被定为 `string[]` 并由 `readTools` 原样拷贝。要把卡片填满，需要把产品路由与网关的 grant/view 这一对都改成携带 `{name, description}`，而这两个文件都不属于本包。浏览器这一半已经写完并有测试：带描述的条目会渲染，裸名字仍然读得懂，而在此期间这里不会编造任何一句话。
- **区块分不出服务器是启用还是停用。** 面向浏览器的契约不报告启用标志，也不报告归属范围，所以行里两者都不显示，而不是去猜；需要这个区分的读者请到 Studio 上看。
- **目前还没有产品提供 `/auth/plugins`，所以在现有的每个部署里目录都读作 `unsupported`。** 浏览器这一半已经完成，并且是对着目录自己的行测过的；缺的是产品端的 `/api/desktop/plugins`，它今天回 404，而 `/api/desktop/mcp` 和其余几条都回 401。资料源读取的回应字段是固定的，写在 `directory-source.ts` 里，所以把那条路由上线是剩下的唯一一步。
- **目录显示的插件名字就是目录里存的样子。** 大部分是 slug 形式（`gl-reconciler`、`kyc-screener`），只有 `text-transform: capitalize` 把它们和标识符区分开，于是渲染成 `Gl-Reconciler`。在浏览器里重写它们等于本包替别人的产品编名字；该修的地方在目录资料。
- **目录里没有任何发行方上传过标记，所以每一行都画首字母。** `iconUrl` 有就会读、就会渲染——产品那边确实有这个字段，存成 `NOT NULL DEFAULT ''`——而首字母方块对每一行都是中性的，这是刻意的：一个插件一个颜色，等于本包替别人的产品发明品牌识别。
- **页面打开时会盖住侧边栏。** `shell.overlay` 横跨整个框架，而布局所有者没有为「落在导航栏旁边的表面」声明座位。页面自己的返回控件与 Esc 就是出口；要做成侧边栏旁边的页面，需要在 [`ui-layout`](../ui-layout/README.zh.md) 新增座位。
