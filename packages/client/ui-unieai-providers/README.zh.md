# @unieai/uad-client-ui-unieai-providers

[English](README.md) | 中文

一个 `settings.section` 条目 —— **API Provider 设置** —— 以 UnieAI Copilot 网页版同名页面的呈现方式，显示该 UnieAI 账号的 OpenAI 兼容 Provider，提供把新 Provider 加进同一份列表的「添加 Provider」控件，也提供逐行的编辑与删除。

本节的要点是：列表只有一份。这里的每一行都是网页版 `user_providers` 中的同一行；本包不保存副本，不向 `settings.yaml` 写入任何内容，也不从中读取。因此在这里添加、改名或删除的 Provider，也就在网页版页面上被添加、改名或删除——原因很简单，它就是同一条记录，而不是被同步出来的第二份。

## 一行提供什么，以及由谁决定

**自备（BYO）的行会打开完整的卡片**：显示名称、Prefix、连接地址、凭据、启用开关、逐模型选择，以及藏在确认之后的删除——确认会说明该 Provider 的模型会一并消失。卡片只判断它独自就能判断的事：名称留空、Prefix 不是 4 位英数字。Prefix 是否可用、该行是否仍然存在，都是产品的答案，由它拒绝时给出的标识符渲染。

**Studio 托管的行会打开更窄的卡片，并把原因说出来。** 产品对这样的行只接受两件事——逐模型选择与整体启用旗标——因为它的凭据、连接地址与模型目录都属于 Studio 绑定，而它的移除方式是解除该账号的绑定，不是删除这一行。本页正好只画这两样，把其余标注为 Studio 所有，也不提供删除。这不是把规则抄了一份：规则住在行旁边的 `lib/studio/managed-provider-rules.ts` 里，以 409 强制执行；若某一行在读取与保存之间变成托管，本页仍会把那个 409 渲染出来。画出完整表单、让拒绝在事后抵达，等于要读者先打完字才知道有这条规则。

**这里不自行检查 Prefix、方案上限或托管规则。** 桌面版看不到账号里其他的 Prefix；把产品的规则再抄一份，正是两边对「什么是合法的编辑」逐渐产生分歧的方式。

## 本节不做的事

**不显示本机 Provider。** 桌面版自己的 Provider 位于「模型」一节，落在 `settings.yaml` 上，凭证存在本机的凭证库中。它们是生命周期不同的另一个存储；把两份列表合并，等于告诉读者在一处删除也会在另一处删除。

**永远不会收到 Provider 凭证。** 创建时，以及编辑时重新输入了 Key 时，会把 API Key 送往产品——那才是要花用它的存储；返回方向不携带任何 Key：`ProviderRow` 没有存放它的字段，因此也没有哪个成员会在日后被无意填上。因此编辑卡片的 Key 字段一开始是空的，并写明留空的含义：留空时补丁里根本不含 `apiKey`，因为空字符串抵达产品会被读作「抹掉已存的凭据」，一次改名就会悄悄弄坏该 Provider。

## 如何抵达账号

经由登录闸门的 `GET`/`POST /auth/providers` 与 `PATCH`/`DELETE /auth/providers/<id>`，由 [`@unieai/uad-unieai-web-gate`](../../unieai/web-gate/README.zh.md) 提供。这层间接正是安全决策所在：认证产品 `/api/desktop/*` 的 API Key 存放在闸门位于宿主的会话表中，不得进入页面，所以由浏览器问宿主、宿主问产品。

未挂载闸门的组合在该路径上没有任何回答，本节会渲染「无法读取」并给出重试控件。它绝不会凭空造出 Provider，也绝不会用空列表顶替一次失败的读取——「账号没有 Provider」与「没能问到」是两个不同的事实。

列表每份文档读取一次，每次写入之后再读一次。之所以重读而非就地修补：产品在存储该行时会规范化 Prefix 并抓取模型目录，对托管行的保存又是以同步的视角回答选择结果，把提交的内容回显出来，等于展示存储里并不存在的东西。

## 文案

凡是网页版已发布的文案，均逐字取自其 `messages/{en,zh-tw,zh-cn,ja}.json`，并在 [`src/client/locales.ts`](src/client/locales.ts) 中于每行旁标出来源键。两个产品呈现同一份列表，就不该互相改写措辞。`API URL` 与 `API Key` 在参考实现的标记中于所有语言下都是字面量，这里同样保持字面量。四种发布语言各自带有完整词典。属于本包自己措辞的有两类：网页版不可能出现的状态——未登录、宿主不可达、列表仍在读取——以及产品只以硬编码繁体中文写在路由处理器里的那两句托管说明：它们的 zh-TW 逐字采用该路由的文字，其余语言是它的翻译。

## 样式

只用 CSS Modules 与语义化 `--dsw-alias-*` token，不写字面颜色，也不使用品牌色。路由 Prefix 用等宽字体并按等宽的方式排布，因为那是会被逐字复制与比对的值。

## Model Experience

无。本包只贡献浏览器端呈现；它所列出的 Provider 属于网页版产品，这里没有任何东西会进入模型请求。

#### KV Cache effect

无；本包既不组装也不发送 provider 请求。

## Known Limitations and Deferred Work

- **列出的 Provider 尚不能供本桌面版自己的 Agent 使用。** 本节展示并添加账号的云端 Provider；要让它们成为本机可选的模型，需要把它们物化为 `llm-pi-ai` 路由，而这需要桌面版刻意不持有的凭证。`GET /auth/models` 现在会回报账号有权运行哪些模型——见[闸门的 Model 路由](../../unieai/web-gate/README.zh.md)——但它做的仅止于回报：产品不随之下发端点，也不下发凭证，更没有公开任何本桌面版 API key 可送出一次回合的按使用者推理路由，因此这里仍然没有任何本地 Agent 能拨打的东西。把其中之一列进编辑器的模型选择器，等于在选单里放上一被选取就会失败的名字。在产品长出那条路由之前，这里是账号管理界面，不是模型来源。
- **没有模型目录同步，也不能编辑目录本身。** 网页版每行都有「同步模型」控件，每个模型都有模态开关；两者写的都是 `modelList`，其条目是目录对象，而不是本桌面投影所回报的纯 id。因此 `PATCH /api/desktop/providers/<id>` 直接拒绝 `modelList`（`model_list_unsupported`），而不是让一次桌面往返把目录压平。托管行的说明文字仍写着请按「同步模型」，因为那句是网页版已发布的文案并被逐字采用；本页并没有这个控件。
- **提交前不检查 Prefix 是否可用。** 桌面版看不到账号里其他的 Prefix，因此被占用的 Prefix 是从产品的拒绝中得知，而不是在输入框里被拦下。
- **一次保存会送出全部可编辑字段，而不只是被改动的那些。** 因此两台桌面同时编辑一行时以最后写入者为准，与两个浏览器分页在参考页面上的表现完全相同；两边都没有冲突解答可给，在这里发明一个只会让两边产生分歧。
- **列表不会自行刷新。** 它每份文档读取一次、每次写入后再读一次；在别处改动的 Provider 会在下一次重试或重新加载时出现，因为没有任何机制把 Provider 变更推送给桌面版。
