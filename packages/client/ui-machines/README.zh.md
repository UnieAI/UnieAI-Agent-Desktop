# @unieai/uad-client-ui-machines

[English](README.md) | 中文

一段對話的工作發生在哪一台機器上——在開始工作的地方顯示，也在那裡選擇。

## 它在哪裡

輸入框工具列的**尾端**，在送出鍵旁邊那組圖示裡，因為工作在哪裡跑是輸入框本身的常態事實，而不是進入一輪對話途中要讀的東西。

它坐的是**常駐**座位（`conversation.input.chrome.end`），而不是綁 session 的那個。那個座位的存在正是為了這件事：一個人在選機器的時候，未必已經開始一段對話；而在遠端機器上，他能挑哪些資料夾，取決於這個答案。列尾這個座位跟另一端的孿生座位（`conversation.input.chrome`）在每個方面都相同，只差渲染在哪一端。

遠端機器不用打開任何東西就看得出跟本機不同：在本機時觸發器只是一個筆電圖示，而工作一旦離開這台電腦，它就長出那台機器的名字。工作離開一個人自己的電腦，不該是要在選單裡才發現的細節，而光憑一個圖示也說不出是哪一台機器。

選單用的是那一列每個下拉選單共同的卡片——模型選擇器的材質與尺寸——所以在兩種主題下它都屬於同一套。在 hero 輸入框時往下展開，輸入框一旦停靠到底部就往上展開，依據的是殼的 phase 而不是量測到的空間：逐字稿欄會長到輸入框需要的高度，所以往下的選單永遠「放得下」，然後蓋住打開它的那個控制項。機器一多，清單會在選單內捲動，而「新增機器」與下方的提示留在原位。

## 它宣告什麼

換機器是整個 client 的事實，不是這個控制項的事實：它以 `machines/changed` 宣告（由 client runtime 宣告型別，所以這個套件與它的聽眾彼此都不必相依），而且只在機器真的移動時才發。被拒絕的切換，以及重選當前這台，都沒有讓執行世界離開原處。

今天真正重要的聽眾是[監控條](../ui-machine-gauges/README.zh.md)。它的讀數描述的是採樣當下那台機器，所以移動之後那份讀數不是「舊的」——它講的是別的地方。

## 每台機器有自己的工作區

工作區是一個路徑，而路徑屬於它所在的那台機器。某人在建置主機上選的資料夾，在他的筆電上並不存在；把它跨機器帶過去，等於把下一個指令指向一個不存在的目錄 —— 那正是使用者看到的「我選了資料夾，它馬上跳回『選擇資料夾』」。

所以一次切換會**記下正要離開的那台機器的工作區**，並**還原正要進入的那台上次待的那一個**。這份紀錄是 host 自己那個機器設定區塊上的一個欄位（`workspaceByMachine`），以機器 id 為鍵，因此它跟「目前是哪台機器」一樣能撐過重啟。瀏覽器半邊自己拼出那個區塊的名稱，而不是把 host 套件匯入 client bundle；有一個測試同時匯入兩邊，斷言它們仍然一致。

抵達一台還沒有人工作過的機器時，畫面上原本開著的東西維持不動。沒有東西可以還原，而「沒有工作區」是使用者自己選的狀態，不該由一次切換強加給他。一個已經不存在的記憶工作區會被跳過，理由相同。

## 它讀什麼、什麼時候讀

清單在選單打開時抓取，不快取也不監看。機器來自一個使用者在 Rabi 之外編輯的檔案——而快取過的清單，恰恰會在「他剛剛加了那台正在找的機器」時是舊的。

讀取失敗時，畫面上已有的機器會留著。還看得到清單的人，仍然可以選另一台，而那往往正是脫離當前故障的方法。

## 新增、移除，以及其他

兩者都是**對話框**，不是在選單裡長出來的列。兩者都會寫進使用者自己的 SSH 設定，而那跟「挑下一個指令在哪裡跑」是不同性質的動作：一個五格表單在機器清單裡展開，會把它正在講的那些機器擠出畫面；而一個渲染成「多一列」的確認，用關掉選單的同一次外部點擊就會被解散掉。打開任何一個都會先關掉選單。

**新增**是往使用者的設定檔末尾附加一個區塊。只寫他填了的欄位——一個被寫成預設值的選項看起來就像一個決定，而下一個讀的人分辨不出來——而且檔案裡原本有的東西一個位元組都不會動。

這個對話框是寫給沒聽過 SSH 的人看的。它從一張圖開始——這台電腦、一條連線、正在加入的那台機器——因為下面那些欄位預設了人已經知道「新增一台機器」是什麼意思。看得見的只有三格（名稱、位址、帳號，每一格標籤在上、一句白話說明在下，而不是打第一個字就消失的 placeholder）；連接埠、金鑰檔與設定檔預覽收在一個摺疊區裡，而它的標題直接寫出裡面有什麼，所以需要的人仍然找得到。

**預覽就是把那條規則畫出來。** 它顯示的正是這次寫入會附加的那幾行，隨欄位即時更新，而留空的欄位一行都不會產生。決定這件事的是匯出的 `previewLines`，而它就是寫入端遵循的同一條規則。

**移除**會拿掉那台機器的整個區塊，並且在無法乾淨移除時拒絕：與其他機器共用同一行 `Host` 的 alias、或是在 `Include` 進來的檔案裡宣告的機器，都會被拒絕並**說明是哪一種**，因為這兩種編輯都會動到另一台機器依賴的那一行。寫入之前會先問，因為那是使用者的檔案。

**測試**會問這台機器現在有沒有回應，跑在 batch 模式，所以需要 passphrase 的機器回報的是 OpenSSH 自己的訊息，而不是停在沒有人看的提示前面。

其餘一切都交給**開啟 SSH 設定**，把檔案交到使用者自己的編輯器手上。用表單編輯既有的機器是刻意不做的：SSH 設定有語法、註解、順序，以及這個產品從沒聽過的選項；一個把它解析成欄位再寫回去的表單，第一次存檔就會把它們弄丟，而且不會有任何東西告訴你。

## Model Experience

無。此套件不註冊任何 tool、prompt、schema 或 context：它讓使用者看到工作在哪裡執行、並可以更改，而模型從來不會被告知自己在哪一台機器上。

#### KV Cache effect

無。這裡不貢獻任何 prompt 片段、工具定義或 context 條目，因此不會移動任何重用邊界。

## 已知限制與未完成項目

- **切換一次影響全部。** 當前機器是整個應用共用的一個值，所以已經開著的對話，下一個指令會送到新選的機器。要做到每段對話各自一台，需要一份 harness 目前還沒有的紀錄。唯一會跟著機器走的是工作區（見上），已經開著的對話不會。
- **資料夾選擇器瀏覽的仍是這台電腦。** 選了遠端機器會改變指令與檔案的去處，但 workspace 的瀏覽對話框讀的是 host 自己的檔案系統，所以顯示的是本機資料夾。遠端 workspace 目前可以用路徑建立，還不能從那個對話框挑。
- **機器出現在清單裡是因為它被設定過，不是因為它有回應。** 選單打開時不做探測；一台關機的機器，在有人按下「測試」或指令真的執行之前，看起來跟開著的一模一樣。
- **既有的機器不能在這裡編輯。** 新增與移除都是整塊操作，那正是它們安全的原因；要改其中一個欄位，就得打開檔案。
- **表單只有五個欄位。** 名稱、主機、使用者、埠、金鑰檔涵蓋一台直接連得到的機器；其他的——超過一層的跳板、agent 轉發、各種 per-host 選項——寫在檔案裡。
