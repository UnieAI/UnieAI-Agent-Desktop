# @unieai/uad-client-ui-machines

[English](README.md) | 中文

一段對話的工作發生在哪一台機器上——在開始工作的地方顯示，也在那裡選擇。

## 它在哪裡

輸入框的工具列，就在資料夾（workspace）晶片旁邊，因為機器跟工作目錄屬於同一個問題：*我接下來要問的事，究竟在哪裡執行。*

它坐的是**常駐**座位（`conversation.input.chrome`），而不是綁 session 的那個。那個座位的存在正是為了這件事：一個人在選機器的時候，未必已經開始一段對話；而在遠端機器上，他能挑哪些資料夾，取決於這個答案。

遠端機器不用打開任何東西就看得出跟本機不同。工作離開一個人自己的電腦，不該是要在選單裡才發現的細節。

## 它讀什麼、什麼時候讀

清單在選單打開時抓取，不快取也不監看。機器來自一個使用者在 Rabi 之外編輯的檔案——而快取過的清單，恰恰會在「他剛剛加了那台正在找的機器」時是舊的。

讀取失敗時，畫面上已有的機器會留著。還看得到清單的人，仍然可以選另一台，而那往往正是脫離當前故障的方法。

## 新增、移除，以及其他

**新增**是往使用者的設定檔末尾附加一個區塊。只寫他填了的欄位——一個被寫成預設值的選項看起來就像一個決定，而下一個讀的人分辨不出來——而且檔案裡原本有的東西一個位元組都不會動。

**移除**會拿掉那台機器的整個區塊，並且在無法乾淨移除時拒絕：與其他機器共用同一行 `Host` 的 alias、或是在 `Include` 進來的檔案裡宣告的機器，都會被拒絕並**說明是哪一種**，因為這兩種編輯都會動到另一台機器依賴的那一行。寫入之前會先問，因為那是使用者的檔案。

**測試**會問這台機器現在有沒有回應，跑在 batch 模式，所以需要 passphrase 的機器回報的是 OpenSSH 自己的訊息，而不是停在沒有人看的提示前面。

其餘一切都交給**開啟 SSH 設定**，把檔案交到使用者自己的編輯器手上。用表單編輯既有的機器是刻意不做的：SSH 設定有語法、註解、順序，以及這個產品從沒聽過的選項；一個把它解析成欄位再寫回去的表單，第一次存檔就會把它們弄丟，而且不會有任何東西告訴你。

## Model Experience

無。此套件不註冊任何 tool、prompt、schema 或 context：它讓使用者看到工作在哪裡執行、並可以更改，而模型從來不會被告知自己在哪一台機器上。

#### KV Cache effect

無。這裡不貢獻任何 prompt 片段、工具定義或 context 條目，因此不會移動任何重用邊界。

## 已知限制與未完成項目

- **切換一次影響全部。** 當前機器是整個應用共用的一個值，所以已經開著的對話，下一個指令會送到新選的機器。要做到每段對話各自一台，需要一份 harness 目前還沒有的紀錄。
- **資料夾選擇器瀏覽的仍是這台電腦。** 選了遠端機器會改變指令與檔案的去處，但 workspace 的瀏覽對話框讀的是 host 自己的檔案系統，所以顯示的是本機資料夾。遠端 workspace 目前可以用路徑建立，還不能從那個對話框挑。
- **機器出現在清單裡是因為它被設定過，不是因為它有回應。** 選單打開時不做探測；一台關機的機器，在有人按下「測試」或指令真的執行之前，看起來跟開著的一模一樣。
- **既有的機器不能在這裡編輯。** 新增與移除都是整塊操作，那正是它們安全的原因；要改其中一個欄位，就得打開檔案。
- **表單只有五個欄位。** 名稱、主機、使用者、埠、金鑰檔涵蓋一台直接連得到的機器；其他的——超過一層的跳板、agent 轉發、各種 per-host 選項——寫在檔案裡。
