# @deepseek-ai/dsh-unieai-mcp-supervisor

[English](README.md) | 中文

挂载已登录 UnieAI 账号所授予的 MCP 服务器：每台服务器一个 `dsh-mcp-client` 实例，并在凭证过期之际持续维持挂载。

网页产品代用户托管 MCP 服务器，并为每台服务器向桌面端发放一枚短效的、按用户签发的 bearer。`dsh-mcp-client` 正好能拨通这类服务器，但它由 `cordis.yml` 配置，而编排文件既不知道某个账号连接了哪些服务器，也拿不到登录时才铸出的凭证。本包就是介于两者之间的那一块。

```yaml
- id: unieai-mcp-supervisor
  name: '@deepseek-ai/dsh-unieai-mcp-supervisor'
```

## 服务器从哪里来

`@deepseek-ai/dsh-unieai-web-gate` 提供 `ctx.unieaiGate`，其 `mcpServers()` 以闸门会话的 API key 代理产品的 `/api/desktop/mcp`。这是一次 HOST 侧读取：返回的授权带有端点与 bearer，而这两者都不会被闸门自己的 `/auth/mcp` 路由送往浏览器。页面拿到的是一个 origin 与一份工具清单；本包拿到的是拨通该服务器所需的东西。

这些是产品自己托管并代理的服务器。账号自有的远端 MCP 条目不在其中，也不可能在其中：产品只把那些条目公布为 origin，因为远端 MCP URL 的路径里经常带着令牌。

## 过期，以及为什么刷新即重挂

每枚 bearer 大约只管一小时，`expiresAt` 说明何时失效。一台 bearer 已过期的已挂载服务器会让每次调用都失败，且没有任何其他信号——没有断线，没有重连，只有拒绝——所以坐等通知不是选项。

监管者在自己持有的最早过期时刻之前 `refreshSkewMs` 重新读取清单，并把等待时间夹在 `minRefreshMs` 与 `maxRefreshMs` 之间。无法解析或已经过去的过期时刻一律落到下界：一个没有回报时间戳的产品版本，发出的仍是一枚会失效的令牌，而对未知寿命唯一安全的读法就是把它当作很短。

每次重读都会铸出新的 bearer，而 `dsh-mcp-client` 在构造时就固定了自己的请求头，没有可供替换的缝。因此把新 bearer 装到连接上的唯一办法就是换一条连接：实例先释放、再挂载，顺序不能反，因为它占用的工具命名空间不能被同时持有两次。另一种做法——让旧连接留着——得到的是一台悄无声息坏掉的服务器，而不是短暂缺席的服务器。

读取失败则什么都不改。已挂载的实例会一直工作到其授权真正失效为止，下一次尝试在 `retryDelayMs` 之后；因为一次 HTTP 调用失败就丢掉全部工具，等于把一瞬间的抖动放大成账号整套工具的损失。

## 生命周期

| 事件 | 发生什么 |
|---|---|
| 插件挂载 | 立刻读取一次——会话可能已经存在，因为重载插件树不会让任何人登出。 |
| `unieai-gate/session` | 读取一次，无论会话往哪个方向变化。 |
| 刷新计时器 | 读取一次，时点由持有的最早过期时刻推算。 |
| 已登出 | 释放全部实例；在会话回来之前不再读取。 |
| Fiber 释放 | 等在途的对账落定后，释放全部实例。 |

若某份授权的 `id` 不是合法的工具命名空间（`[A-Za-z0-9_-]{1,32}`），则记一条警告并跳过，而不是交给 `dsh-mcp-client`——后者会因此让自己加载失败，并连带拖垮该次读取剩下的服务器。

## 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `refreshSkewMs` | 5 分钟 | 提前多久重读最早过期的那份授权。这段余量要覆盖读取、断开与重连。 |
| `minRefreshMs` | 30 秒 | 等待时间的下界；也用于覆盖无法解析或已经过去的过期时刻。 |
| `maxRefreshMs` | 30 分钟 | 等待时间的上界。它限定一份授权最久可以多久不被查验，也是没有任何挂载时的读取节奏，从而无需产品发信号即可发现新连接的服务器。 |
| `retryDelayMs` | 60 秒 | 读取失败后的等待。与下界分开，因为读取失败并不说明授权何时失效。 |
| `toolCallTimeoutMs` | 60 秒 | 交给每个已挂载实例的单次工具调用超时。 |

## 消费的服务

| 服务 | 用途 |
|---|---|
| `ctx.unieaiGate` | 读取已登录账号及其持有的 MCP 授权。 |

每个已挂载实例自行注入 `ctx.tools`；本包从不直接触碰工具注册表。

## Model Experience

Indirectly, through the `dsh-mcp-client` instances it mounts, which own every discovered tool's name, schema, and result.

#### KV Cache effect

在已挂载集合及其发现的工具不变期间，前缀稳定。每个刷新周期都会重挂所有 bearer 被重铸的服务器，而一次恢复出相同工具清单的重挂会重现完全相同的定义，因此按小时的周期本身是前缀稳定的；若某个周期里账号的服务器或其工具确实发生了变化，则定义被替换，并可能从第一个改变的 schema token 起使复用失效。

## Known Limitations and Deferred Work

- **刷新周期会断开连接。** `dsh-mcp-client` 在构造时固定请求头，因此新 bearer 需要新实例。在释放与替代实例完成发现之间的那一刻，工具是缺席的，旧实例上在途的调用会失败。要消除这个空档，需要在 `dsh-mcp-client` 上开一道请求头刷新的缝，而目前没有别的消费方需要它。
- **决定节奏的通常是上界而非提前量。** 产品铸出的是一小时的授权，而 `maxRefreshMs` 默认 30 分钟，因此常规周期是在授权寿命过半时重挂，而不是在其末尾前五分钟。这是安全且刻意的——同一个计时器也负责发现新连接的服务器——但代价是每份授权多一次重挂。
- **闲置会话的失效不被观察。** 闸门会话按闲置过期，而该过期是在读取时判定的，因此没有任何东西宣告它。本包会在下一次预定读取时才察觉，在那之前仍为一个已不再登录的账号持有实例。那些实例依然可用：MCP bearer 属于产品，其寿命长于浏览器会话。
- **只有产品自己的服务器可挂载。** 账号个人的远端 MCP 条目只被公布为 origin 而非端点，因此这里没有任何东西能拨通它。要改变这一点是产品的决定，不是本包的。
- **没有面向用户的界面。** 因 id 非法而被跳过的服务器，或连接持续失败的服务器，只体现为一行 host 日志。插件页读的是 `/auth/mcp`，那报告的是账号被授予了什么，而不是本 host 实际挂载了什么。
