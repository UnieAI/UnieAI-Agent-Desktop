# @unieai/uad-ssh-server

[English](README.md) | 中文

一台真的 OpenSSH 伺服器，為一次測試執行而起，用完就丟。

## 它為什麼存在

那些用來證明遠端機器能運作的測試套件，過去都是 `describe.skipIf(!ready)`，門檻是兩個指向「某人手動架好的伺服器」的環境變數。在每一次一般執行裡——包括 CI——它們都**靜靜地**跳過，而遠端這條路就這樣完全沒有涵蓋地出貨了。

有三個缺陷因此抵達使用者：

- 一個被手動建構、卻沒有拿到機器簿的路由 subprocess provider，
- 一個可以自由地在行程繼承來的任何終端機上要密碼的客戶端——它會讓指令停住，直到有人在一個他根本沒在看的終端機裡打字，
- 一個從 `HOME` 解析出來的設定檔路徑，而 OpenSSH 讀的是密碼資料庫，於是機器清單和連線讀的是不同的檔案。

每一個都是「真的連一次就會發現」的那種。

所以伺服器是**由測試自己**起的。跳過不再是預設值，而唯一還會造成跳過的原因是這台機器沒裝伺服器軟體——那時它會說出來，並列出它找過哪些路徑。

## 它是什麼

只綁 loopback，連接埠由作業系統挑，主機金鑰與用戶端金鑰每次執行重新產生、結束後刪除。它只認金鑰、直接拒絕密碼，所以套件裡沒有任何東西能卡住等一個人。

這證明的正是 mock 證明不了的事：這個 repo 組出來的 argv 是真正的客戶端會接受的，而且指令真的抵達了另一端。

`DSH_SSH_TEST_CONFIG` 與 `DSH_SSH_TEST_ALIAS` 兩個都設好時仍然優先，所以任何人都可以改成指向一台真的機器。

## Model Experience

None，因為這個套件是測試 fixture，不會被組裝進任何產品 runtime；它不註冊任何工具、提示、schema 或 context。

#### KV Cache effect

None。它不貢獻任何提示片段、工具定義或 context 條目，所以沒有任何重用邊界會因為它而移動。

## 已知限制與未完成項目

- **只支援 POSIX。** 伺服器是主機上的 `sshd`，在三個固定路徑尋找；Windows 沒有對應物，所以用到它的套件在那裡不會執行。
- **只有一個帳號，就是目前使用者。** 產生的設定會以執行測試的人登入，所以任何「對面是不同使用者」的情境都無法表達。
- **沒有 sftp 子系統。** 只涵蓋 exec 通道做得到的事；需要 `sftp` 的套件得自己加上子系統設定與有那個執行檔的伺服器。
- **沒有模擬慢速或不穩的連線。** 每一條連線都是 loopback 且即時，所以逾時與重試行為仍然只靠注入時鐘的單元測試涵蓋。
