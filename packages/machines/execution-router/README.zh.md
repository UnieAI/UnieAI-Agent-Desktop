# @unieai/uad-execution-router

[English](README.md) | 中文

執行世界，路由到使用者正在工作的那台機器。

## 它做什麼

取代單一的 provider 配對掛載後，`RoutedFileSystem` 與 `RoutedSubprocessRuntime` 註冊 `ctx.fs` 與 `ctx.subprocess`，並把每一次呼叫轉送給某一台機器的 provider——這台電腦，或是透過 SSH 連到的某一台。接縫之上什麼都不用改：Bash 工具、檔案工具、搜尋、language server 與終端機仍然只消費兩個介面，而它們落在哪一台機器上，變成使用者當下的選擇，而不是開機時就定死的組合決定。

兩者必須一起掛載、而且必須指向同一台機器，因為它們是**一個**執行世界。檔案系統在一台、指令在另一台，會用一種沒有任何消費端偵測得到的方式破壞這個接縫最核心的承諾。

## 一次呼叫怎麼找到它的機器

這裡其實藏著兩個問題，答案不同：

- **指名 TARGET 的呼叫，機器就在參數裡。** 遠端 provider 會把機器名蓋在 target key 上，所以讀一個稍早解析出來的檔案，會回到它原本那台機器。這正是讓 target 能跨越切換繼續使用的關鍵：在使用者換機器之前拿到的檔案，不會悄悄變成另一台上同名的另一個檔案。
- **指名 PATH、或什麼都不指名的呼叫，是環境相關的。** 啟動指令、解析相對路徑、要一個終端機，都屬於「當前那台機器」，因為參數裡沒有任何東西能說明別的。

跨機器的包含關係回答 `false` 而不是錯誤：問「這裡的目錄有沒有包含那裡的檔案」是個合理的問題，而它有個平實的答案。

## 世界

一台機器一個世界，第一次用到時建立，之後保留——切回去時連線還開著，而從沒用過的機器不花任何成本。

每個世界都是在**隔離的子 context**（`ctx.isolate('fs')`）裡建構的真正 provider，那個 context 的服務欄位與父層分開。這正是這個套件能夠自己註冊成唯一的 `ctx.fs`、同時私有地持有好幾個其他 provider 的原因。

兩個接縫的建法不同，而其中一種能付的代價，另一種付不起。

**檔案系統**的 world 走外掛生命週期掛載（`world.plugin(...)`），因為它的 provider 都宣告了注入——本機那個帶沙箱的要 `sandboxPolicy`，遠端那個要機器名冊——而**只有外掛生命週期會兌現一個宣告過的注入**。用 `new` 建出來的 provider 坐在一個沒有 inject 清單的 context 上，它自己的讀取會被 context proxy 拒絕（`cannot get property "sandboxPolicy" without inject`），於是這個接縫看起來掛上了，實際上什麼都答不出來。檔案系統上真正要緊的方法本來就都是非同步的，所以等它掛完，呼叫端察覺不到任何代價。

**subprocess** 的 world 則是直接建構，因為 `spawn` 是同步發佈一個活的 handle——呼叫端下一行就可能往子行程的 stdin 寫東西，而一個「串流稍後才出現」的 handle 會弄壞那些接縫契約本來就允許的呼叫端。這條路付得起，只因為兩個 runtime 都不需要注入才能工作：本機那個一個都沒宣告，遠端那個則是把機器名冊當建構參數交給它，而不是去讀一個沒宣告的服務。直接建構出來的 provider，它自己的 schema 在這裡套用——schema 的預設值是外掛生命週期的工作，而直接建構跳過了它，一個拿到裸 `{}` 的 provider 會拒絕自己的設定。

## Model Experience

間接的，透過所有建立在這兩個接縫之上的工具——Bash 執行器、檔案工具、搜尋——由它們擁有面向模型的契約；此套件自己不註冊任何 tool、prompt 或 schema，只改變它們的工作發生在哪一台機器上。

#### KV Cache effect

無。這裡不產生任何 prompt 片段、工具定義或 context 條目。

## 已知限制與未完成項目

- **環境相關的呼叫會跟著當前機器走，包含進行中的 session。** 一個在某台機器上開始的對話，下一個指令會送到「當前」那台機器，因為 spawn 本身不帶任何機器資訊。要做到每個 session 或每個 workspace 各自路由，需要一份說明「這個 session 屬於哪台機器」的紀錄。
- **切換不會搬動任何東西。** 在前一台機器上打開的檔案、正在跑的終端機、已啟動的 language server 都留在原地；沒有東西被遷移，也沒有東西被關閉。
- **世界不會被拆掉。** 用過一次的機器會保留它的 provider——遠端的話還包含那條重用連線，直到 OpenSSH 自己的閒置窗到期——直到 router 被釋放為止。
